# 第四章 操作系统知识

## 1. 嵌入式操作系统：题干关键词要对应到特性

| 特性 | 题干常见线索 | 判断重点 |
|---|---|---|
| 微型化 | 资源受限、代码量小、成本低、占用少 | 体积、资源与成本 |
| 可定制性 | 硬件变化、结构或功能配置、缩短研发周期 | 按需求裁剪、配置系统 |
| 实时性 | 及时响应、截止时间、过程控制、通信、多媒体 | 响应时间可预期 |
| 可靠性 | 容错、防故障、关键任务、稳定运行 | 失效预防与恢复 |
| 易移植性 | HAL、BSP、迁移到另一平台 | 降低迁移改造成本 |

题干强调“针对硬件变化进行结构与功能配置”时，决定性词是**配置**，故考查可定制性；若强调 HAL、BSP 使迁移改动少，才考查易移植性。

## 2. 存储管理：段页式逻辑地址、虚拟存储与页面置换

### 页式存储管理与地址变换计算（十进制计算模型）
- **逻辑地址结构**：由 **页号（Page Number）** 与 **页内地址（偏移量 Offset）** 两部分组成；
- **地址变换标准计算步骤**：
  设系统页面大小为 L 字节，用户给出的逻辑地址为 A：
  1. **计算页号 P**：P = floor(A / L)（整除取商）；
  2. **计算页内偏移量 W**：W = A mod  L = A - P × L（取模求余，变换过程中**页内地址保持不变**）；
  3. **查页表求物理块号 B**：以页号 P 为索引检索页表，得到对应的物理块号（页框号）B；
  4. **合成物理地址**：
     物理地址 = B × L + W
  - **典型例题推导**：
    > **题目**：页大小为 4K（4096 字节），逻辑地址为 9000（十进制），页表中页号 2 对应的物理块号为 5，求变换后的十进制物理地址。
    >
    > **步骤**：
    > 1. 页号 P = floor(9000 / 4096) = 2；
    > 2. 页内地址 W = 9000 - 2 × 4096 = 9000 - 8192 = 808；
    > 3. 查表：页号 2 对应物理块号 B = 5；
    > 4. 物理地址 = 5 × 4096 + 808 = 20480 + 808 = 21288。计算结果为 21288。

### 段页式存储地址结构与空间计算
- **逻辑地址结构**：由 **段号 + 段内页号 + 页内地址（偏移量）** 三部分组成；
  - 若页内地址为 k 位，则页面大小为 2^k 字节（如 10 位对应 2^10 = 1024 字节 = 1KB，12 位对应 2^12 = 4KB）；
  - 若段内页号为 m 位，则每个段最多允许划分 2^m 个页面；
  - 若段号为 s 位，则系统最多支持 2^s 个段；
  - **典型示例**：若段号占 11 位、页号占 11 位、页内地址占 10 位，则系统**最多可有 2^11 = 2048 个段，每个段最大允许有 2^11 = 2048 个页，页的大小为 2^10 = 1KB**。
- **地址变换过程**：
  1. 系统为每个进程配置 1 个**段表**，通过段号查找到对应段的**页表起始地址和页表长度**；
  2. 根据段内页号查找**页表**，获得对应的**物理块号**；
  3. 物理块号拼接页内地址，合成最终的**物理地址**；
  4. 访问一个数据共需访存 **3 次**（查段表、查页表、访目标单元）。

### 虚拟存储与页面置换算法
- **虚拟存储器本质**：基于程序局部性原理（时间局部性、空间局部性），将**主存与辅存（外存磁盘）** 结合构建的逻辑存储体系；
- **页面置换算法对比**：
  - **最佳置换 (OPT)**：淘汰未来最长时间内不再被访问的页面（理论最优，无法预知未来）；
  - **先进先出 (FIFO)**：淘汰最早进入内存的页面。**可能产生 Belady 异常（增加物理块数故障率反而上升）**；
  - **最近最少使用 (LRU)**：淘汰过去最长时间未被访问的页面（堆栈/寄存器硬件支持，性能接近 OPT）；
  - **时钟置换 (CLOCK / NRU)**：结合**访问位**与**修改位**，优先淘汰 `(访问位=0, 修改位=0)` 的页面（无需写回外存，置换开销最小）。

## 3. 设备管理：SPOOLing、磁盘调度、双缓冲区性能与旋转优化

### SPOOLing（假脱机）与独占设备虚拟化
- **核心目的**：把**独占设备在逻辑上虚拟成共享设备**，使多个进程都可以提交对该设备的 I/O 请求；
- **典型机制**：利用磁盘上的输入井/输出井（spool area）暂存待处理作业，并由专门的输入/输出进程维护队列，再按设备可用顺序驱动物理外设；
- **典型例子：打印机**。多个程序可以同时提交打印作业，但物理打印机仍然一次只打印一个作业；“共享”是操作系统提供的**逻辑共享**，不是让一台物理设备真正并行工作；
- **与普通缓冲技术的区别**：
  - **缓冲**：主要用于缓和 CPU、内存与外设之间的速度不匹配，减少等待并提高 I/O 与计算的重叠程度；
  - **SPOOLing**：更强调**排队、异步提交和独占设备虚拟化**，通常利用磁盘作为大容量中间存储；
- **做题口诀**：看到“假脱机 / SPOOLing / 打印队列 / 独占设备共享”，优先联想到**独占设备 → 逻辑共享设备**。提高并发度、设备利用率或 CPU 利用率可能是间接效果，但不是定义性的主要目的。

### 磁盘存取时间与寻道性能模型
- **磁盘存取时间构成**：
  存取时间 = 寻道时间 + 旋转延迟时间 + 数据传输时间
  - **寻道时间**：磁头移动到目标磁道所需的时间（平均寻道时间由移道距离与每道移道耗时决定）；
  - **旋转延迟时间**：盘片旋转使目标扇区到达磁头下方的时间（平均为盘片旋转半周所需时间）；
  - **数据传输时间**：数据从磁道扇区读出并传送到控制器的时间。
- **非连续文件读取耗时计算**：若文件各逻辑块在磁盘上非连续存放，读取每块均需经历一次独立的寻道（按平均移动磁道数计算）、旋转延迟与传输过程；读取 n 块的总耗时为各块独立存取耗时之和：`T_总 = (寻道时间 + 旋转延迟时间 + 传输时间) × 块数`。

### 磁盘寻道调度算法
- **先来先服务 (FCFS)**：按请求先后顺序寻道，公平但平均寻道时间长；
- **最短寻道时间优先 (SSTF)**：优先响应与当前磁头距离最近的请求。**容易导致两端磁道“饥饿”**；
- **扫描算法 (SCAN / 电梯算法)**：磁头沿一个方向移动并响应沿途请求，到达最外端/最内端后反向扫描；
- **单向循环扫描 (C-SCAN)**：磁头仅沿单向移动服务请求，到达边缘后迅速直接返回起始磁道，返回途中不服务。

### 单缓冲区 vs 双缓冲区通用时间计算模型
设从磁盘读取一个数据块到缓冲区耗时为 T，从缓冲区传输到用户工作区耗时为 M，CPU 处理该数据块耗时为 C。处理连续 n 个数据块的总时间：
1. **单缓冲区处理时间**：
   - 缓冲区是独占临界资源，输入与传送不能同时进行；
   - **单块处理周期**：max(C, T) + M；
   - **处理 n 块总时间**：
     T_总 = (n - 1) × max(C, T) + n × M + T + C
     （当 T 与 C 均大于 M 时，可简化为首块启动时间 T + M 加上后续各块周期流水）。
2. **双缓冲区处理时间**：
   - 两个缓冲区可交替工作：当向缓冲区 1 读入数据时，CPU 与缓冲区 2 可同时进行传送和处理；
   - **单块处理周期**：max(T, C + M)；
   - **处理 n 块总时间**：
     - 若 T > C + M（外设读盘为主导）：T_总 = n × T + M + C；
     - 若 T < C + M（CPU 运算为主导）：T_总 = n × (C + M) + T。

### 磁盘旋转与记录优化分布（交替存放）
- **现象**：当磁头读取完记录 R_1 后，CPU 需要耗费时间 C 对其进行处理；在此期间，盘片保持匀速旋转，当 CPU 处理完毕时，磁头已转过后续紧邻的记录 R_2。若按顺序物理存放，磁头必须等待盘片旋转几乎整整一圈才能重新对准 R_2；
- **非优化耗时**：T_单块 = T_读取 + T_旋转一整周 × (n - 1) + T_处理；
- **优化分布（交替存放）**：根据处理耗时 C 对应的盘片旋转扇区数，将下一个逻辑记录 R_i+1 间隔存放在该时刻磁头正好转到的扇区上，实现读完即处理、处理完即读下一块，使总耗时降至理论最小值：
  T_优化总耗时 = n × (T_单块读取 + T_处理)

## 4. 文件管理：位示图空间、多级索引与文件路径

### 位示图（Bitmap）物理块管理计算
位示图每一位（bit）对应外存的一个物理块（0 表示空闲，1 表示已占用）：
1. **磁盘物理块总数**：
   物理块总数  N = 磁盘总容量 / 单个物理块大小
2. **位示图所需字数**：
   位示图所占字数 = ⌈(物理块总数 N) / 机器字长位数⌉（即 ceil(N / 机器字长位数)）
3. **物理块号与字号、位号的双向转换**：
   - **0 基编号（块号、字号、位号均从 0 开始）**：
     - 块号 n 对应的字号：字号 = floor(n / 字长)；
     - 块号 n 对应的位号：位号 = n mod 字长；
     - 反算块号：n = 字号 × 字长 + 位号。
   - **1 基编号（从 1 开始编号）**：
     - 字号 = floor((n - 1) / 字长) + 1；
     - 位号 = (n - 1) mod 字长 + 1。

### 多级索引结构（UNIX 13 个索引节点模型）
设单个物理块大小为 B，每个盘块地址指针占 P 字节，则一个索引块可容纳的指针数为 K = B / P。
- **直接索引项（0～9 共 10 项）**：直接指向 10 个数据物理块，支持小文件极速访问，容量为 10 × B；
- **一级间接索引（第 10 项）**：指向 1 个索引块，包含 K 个盘块地址，容量为 K × B；
- **二级间接索引（第 11 项）**：指向 1 个一级索引块，下辖 K 个二级索引块，容量为 K² × B；
- **三级间接索引（第 12 项）**：指向三级索引结构，容量为 K³ × B；
- **逻辑块号定位法则**：
  - 逻辑块号 0 ≤ n ≤ 9：通过直接索引访问；
  - 10 ≤ n < 10 + K：通过一级间接索引访问；
  - 10 + K ≤ n < 10 + K + K²：通过二级间接索引访问；
  - 大于 10 + K + K^2：通过三级间接索引访问。

### 绝对路径 vs 相对路径
- **绝对路径（全文件名）**：从根目录出发的完整路径，Windows 必须带盘符（如 `C:\dir\file.txt`），Linux 以单根斜杠 `/` 开头（如 `/home/user/file.txt`）；
- **相对路径**：从当前工作目录出发的路径，**绝对不能以斜杠或盘符开头**（如 `child_dir\file.txt`）。采用相对路径不仅能简化操作，还能显著减少搜索目录的磁盘 I/O 访问次数；
- **文件关联机制**：在 Windows 操作系统中，系统通过建立的“文件扩展名与应用程序关联”来决定使用什么程序打开特定文件（例如用户双击 `.jpg` 文件时，系统自动启动已关联的图像程序）。

## 5. 进程管理、死锁与 PV 操作通用体系

### 线程概念与进程资源共享模型
- **进程与线程的本质区别**：
  - **进程**：系统进行资源分配和保护的独立基本单位，拥有独立的虚拟地址空间、代码段、数据段和系统资源（如文件描述符）；
  - **线程（轻量级进程）**：CPU 独立调度和分派的基本单位，基本不拥有系统资源，仅拥有程序计数器（PC）、一组寄存器和栈等运行必需的私有上下文；
- **线程间资源共享**：同一进程创建的多个线程（如 t1、t2、t3）共享该进程拥有的全部系统资源（包括虚拟地址空间、全局变量、打开的文件列表等）；
- **并发优势与开销**：线程切换开销远小于进程上下文切换，线程间通信更高效，但同一进程内线程并发访问共享资源时需妥善同步以防止竞争条件。

### 进程调度算法：FCFS、SJF、时间片轮转与优先级调度
- **先来先服务（FCFS，First-Come First-Served）**：
  - 按作业/进程到达就绪队列的先后次序进行调度；
  - **特点**：非抢占式，算法简单公平；**利于长作业、不利于短作业**，不利于 I/O 繁忙型作业。
- **短作业优先（SJF，Shortest Job First）**：
  - 优先调度估计运行时间最短的作业/进程；
  - **特点**：能获得最短的平均周转时间和平均等待时间；但对长作业不利，可能导致长作业长期得不到调度而产生**“饥饿”现象**。
- **时间片轮转调度（RR，Round Robin）**：
  - 主要用于分时操作系统。就绪队列按 FCFS 排列，系统为每个进程分配一个固定的时间片 q。时间片用完后进程若未完成，由时钟中断强行剥夺 CPU，该进程送回就绪队列末尾等待下一轮调度。
  - **核心避坑考点**：
    - **时间片过大**：若时间片选取过大（大于所有就绪进程所需的最大执行时间），则每个进程都能在各自的一个时间片内执行完毕，**时间片轮转调度算法将退化为先来先服务（FCFS）算法**；
    - **时间片过小**：进程频繁发生上下文切换，系统吞吐量和效率显著下降。
- **高响应比优先（HRRN，Highest Response Ratio Next）**：
  - 响应比 R = (等待时间 + 运行时间) / 运行时间 = 1 + (等待时间 / 运行时间)；
  - 既兼顾了短作业（运行时间短则 R 大），又避免了长作业无限饥饿（等待时间变长则 R 逐渐增大）。

### CPU 工作状态与系统调用陷入机制
- **两大特权级别工作状态**：
  - **内核态（Kernel Mode / 管态 / 特权态）**：操作系统内核运行时的状态。具有最高特权，能执行包括特权指令在内的所有指令，能访问系统全部物理内存和外设硬件；
  - **用户态（User Mode / 目态 / 用户模式）**：普通应用程序运行时的状态。只能执行非特权指令，不能直接操作底层硬件或访问内核敏感数据结构。
- **系统调用（System Call）的状态切换机制**：
  - 用户程序在用户态下如果需要请求操作系统提供的核心服务（如读写磁盘文件、创建/管理进程、申请物理内存等），必须执行**系统调用（通过“访管指令 / 陷入指令 Trap”）**；
  - 触发后，**CPU 立即由用户态切换到内核态**，由内核例程代为执行受保护的操作，完成后再将结果返回并将 CPU 切回用户态。
- **做题易错陷阱**：
  - **运行态、就绪态、阻塞态（等待态）**是**进程（Process）的调度生命周期状态**，绝对不是 CPU 的工作状态！
  - 题干问“用户程序在用户态下执行系统调用时，CPU 会从用户态切换到（ ）”，考查的是特权级状态，答案严格为**内核态（管态）**，切勿被进程的“阻塞态/就绪态”干扰！

### 前趋图与 PV 操作信号量绑定通用法则
1. **箭线与信号量一一对应**：前趋图中有多少条有向箭线，就设立多少个信号量（如 S_1, S_2, ...）；
2. **入度执行 P 操作（请求资源/前驱同步）**：箭线指向进程 P，说明该前驱是进程 P 启动的前提，因此在进程 P 开始前必须执行该信号量的 **P(S) 操作**；
3. **出度执行 V 操作（释放资源/唤醒后继）**：从进程 P 引出指向后继的箭线，说明进程 P 结束后需唤醒后继，因此在进程 P 结束后必须执行对该信号量的 **V(S) 操作**；
4. **口诀**：**前出 V 后入 P，前驱完成后 V 释放，后继启动前 P 阻塞等。**

### 死锁预防、避免与不发生死锁的最小资源数定理
1. **死锁产生的 4 个必要条件**：互斥条件、请求与保持条件、不剥夺条件、环路等待条件；
2. **银行家算法（死锁避免）**：在分配资源前进行安全性检查，寻找是否存在至少一个“安全序列”；若分配后系统处于不安全状态，则拒绝分配；
3. **不发生死锁的极限资源数通用公式**：
   若系统中有 n 个并发进程，每个进程最大需要 w 个同类独占资源，则**系统不发生死锁的最小资源总数 M** 为：
   M ≥ n × (w - 1) + 1
   （极端分配：给每个进程都分配 w - 1 个资源使其处于等待状态，此时只要多出 1 个资源，就能使至少 1 个进程运行完毕并释放所有资源，从而激活全盘）。

## 6. 进程状态转换模型与经典进程同步互斥问题

### 进程三态与五态模型转换条件
- **三态模型（运行、就绪、阻塞）**：
  - **就绪态 → 运行态**：获得 CPU 时间片调度（进程调度分配处理器）；
  - **运行态 → 就绪态**：时间片用完，或被更高优先级进程抢占；
  - **运行态 → 阻塞态（等待态）**：进程主动请求某项系统服务或等待某一事件发生（如发起 I/O 请求、等待信号量 P 操作、申请互斥临界资源）；
  - **阻塞态 → 就绪态**：所等待的事件已经发生（如 I/O 操作完成中断响应、被 V 操作唤醒），进程被系统放入就绪队列等待下一轮 CPU 调度；
  - **绝不可行的转换路径**：
    - **阻塞态绝不能直接转换到运行态**！阻塞进程即使获得所需资源，也必须先进入就绪队列重新排队；
    - **就绪态绝不能直接转换到阻塞态**！只有当前正在 CPU 上执行的运行进程才可能触发阻塞。
- **五态模型扩展**：
  - **新建态（创建态）**：进程刚刚被创建，操作系统已为其分配了 PCB，但尚未放入就绪队列；
  - **终止态（退出态）**：进程执行完毕或异常中止，系统正在回收其除 PCB 外的全部内存和系统资源。

### 经典进程同步与互斥问题通用建模
1. **生产者—消费者问题（有界缓冲区）**：
   - 信号量设置：
     - `mutex = 1`：互斥访问有界缓冲区的互斥信号量；
     - `empty = n`：表示当前缓冲区中空闲槽位数量（资源信号量，初值为缓冲区容量 n）；
     - `full = 0`：表示当前缓冲区中已装满产品的数据槽位数量（初值为 0）；
   - 执行顺序规则：
     - 生产者：`P(empty) -> P(mutex) -> 放入产品 -> V(mutex) -> V(full)`；
     - 消费者：`P(full) -> P(mutex) -> 取走产品 -> V(mutex) -> V(empty)`；
     - **做题死锁陷阱**：**必须先申请资源信号量（empty/full），后申请互斥信号量（mutex）**！若颠倒次序（如生产者先 `P(mutex)` 后 `P(empty)`），当缓冲区满时，生产者占有 mutex 阻塞在 empty 上，消费者因拿不到 mutex 无法消费，导致全盘死锁！
2. **读者—写者问题**：
   - 允许多个读者同时并发读取文件；
   - 只允许一个写者往文件中写入；
   - 任何写者操作时不允许任何读者读取。

## 7. 银行家算法安全性检查与死锁四大处理策略

### 银行家算法安全性检查流水线
银行家算法是著名的**死锁避免算法**。系统在分配资源前，先预判分配后系统是否处于“安全状态”。
1. **核心数据结构**：
   - `Available[m]`：系统当前剩余可用的各类资源向量；
   - `Max[n][m]`：各进程对各类资源的最大需求矩阵；
   - `Allocation[n][m]`：各进程当前已分配到的各类资源矩阵；
   - `Need[n][m] = Max[n][m] - Allocation[n][m]`：各进程未来还需要申请的各类资源需求矩阵；
2. **安全状态判定步骤**：
   - 设工作向量 `Work = Available`，标记所有进程为未完成 `Finish[i] = false`；
   - 寻找满足 `Finish[i] == false` 且 `Need[i] ≤ Work` 的进程 P_i；
   - 若找到：假设 P_i 获得资源顺利运行完毕并释放资源，更新 `Work = Work + Allocation[i]`，设置 `Finish[i] = true`，将 P_i 加入安全序列；
   - 重复寻找，直到所有进程的 Finish 均为 true（存在安全序列，系统处于安全状态，可以分配）；
   - 若找不到满足条件的进程，且仍有进程未完成，则说明系统处于**不安全状态**，拒绝本次资源申请。
3. **安全状态与死锁的关系**：
   - **安全状态一定不会发生死锁**；
   - **不安全状态并不等于系统已经死锁**（只是存在死锁的风险，若后续进程不申请到最大需求，系统仍可能正常运行）；
   - **死锁状态必定是不安全状态**。

### 死锁四大处理策略全景对比

| 策略类别 | 核心机制与处理原则 | 实施代价与优缺点 | 典型应用或算法 |
|---|---|---|---|
| **鸵鸟策略（忽略）** | 对死锁不闻不问，假设死锁极罕见发生；若发生则直接人工重启系统 | 零系统运行开销；适合个人 PC 与通用桌面系统 | Windows / Linux 默认桌面策略 |
| **死锁预防** | 严格破坏死锁产生的 4 个必要条件之一（互斥、请求与保持、不剥夺、环路等待） | **限制条件极为苛刻**，资源利用率和系统并发度大幅下降 | **破坏环路等待：资源有序分配法**（所有资源统一编号，必须按序号递增申请） |
| **死锁避免** | 在资源动态分配过程中，使用算法评估系统安全性，防止系统进入不安全状态 | 允许动态并发分配，但需要提前预知进程的最大资源需求，算法计算开销较大 | **Dijkstra 银行家算法** |
| **死锁检测与解除** | 允许死锁发生，系统周期性运行检测算法；发现死锁后采取挂起、撤销进程或剥夺资源予以解除 | 资源利用率最高，但检测算法开销大，回滚撤销进程代价高昂 | **资源分配图化简（死锁定理）**、按优先级撤销死锁进程 |

## 8. 文件存储空间分配方式全景对比

| 分配方式 | 物理存储结构特征 | 存取方式支持 | 文件动态扩充能力 | 存储空间利用率与碎片 |
|---|---|---|---|---|
| **连续分配** | 文件在磁盘上占用一组**连续的物理块** | **支持顺序存取与极速随机存取**（通过首块号加偏移直接计算） | 极差，文件增大需要预先留出足够连续空间或整体搬迁 | 易产生大量外部碎片，需要定期碎片整理 |
| **链接分配（隐式）** | 文件各块离散存放在任意物理块中，每块包含指向下一块的指针 | **仅支持顺序存取**，查找任意块需沿链顺序遍历 | 极好，动态按需增加磁盘块 | 指针占用少量内部空间，可靠性较差（指针断链全文件丢失） |
| **链接分配（显式 / FAT）** | 指针从物理块中剥离，集中保存在内存中的**文件分配表（FAT）**中 | 提高顺序存取速度，通过内存检索 FAT 可较快定位逻辑块 | 极好，灵活扩充 | FAT 表常驻内存占用系统内存空间 |
| **索引分配** | 为每个文件建立一个专用的**索引表（索引块）**，记录该文件所有物理块号 | **完美支持顺序存取与随机直接存取** | 极好，支持超大文件与动态增长 | 小文件存在索引块空间浪费；超大文件需引入多级索引或混合索引 |

## 9. 第四章核心易错陷阱防坑指南与做题检查清单

### 核心易错陷阱防坑指南
1. **CPU 特权态 vs 进程生命周期状态混淆**：
   - **陷阱**：题干问“系统调用时 CPU 切换为什么状态”，错误选成“就绪态”或“阻塞态”；
   - **避坑法宝**：就绪/运行/阻塞是**进程的调度状态**；CPU 的特权级状态只有**用户态（目态）**与**内核态（管态）**。系统调用通过陷入指令从用户态切换到**内核态**。
2. **进程状态转移非法跃迁**：
   - **陷阱**：误以为阻塞态进程在等待事件完成后直接恢复运行；
   - **避坑法宝**：阻塞态进程被唤醒后**只能转为就绪态**，必须重新经过进程调度程序分派 CPU 才能再次运行。
3. **系统不安全状态误判为死锁**：
   - **陷阱**：认为银行家算法检测出不安全状态即代表系统死锁；
   - **避坑法宝**：不安全状态仅仅是可能演化为死锁，只要进程后续实际需求未达峰值，依然可能顺利完成；但死锁状态必然属于不安全状态。
4. **位示图字号与位号计算基数（0 基 vs 1 基）**：
   - **陷阱**：忽视题目中“字号从 0 开始”还是“从 1 开始”，导致公式偏移量计算差 1；
   - **避坑法宝**：0 基编号整除得字号、取模得位号；1 基编号先减 1 再整除取模后分别加 1。
5. **多级索引最大文件容量计算**：
   - **陷阱**：忘记计算每个索引块所能容纳的指针数量 `K = 物理块大小 ÷ 地址指针大小`；
   - **避坑法宝**：直接索引容量 `10 × B`，一级间接 `K × B`，二级间接 `K² × B`，三级间接 `K³ × B`，相加即为文件最大容量。

### 第四章做题自检检查清单
- [ ] 地址题先列字段位数、单位和“最多/恰有”的限定；
- [ ] 磁盘题把寻道、旋转、传输、处理分开，再判断是否可流水重叠；
- [ ] 位示图题统一成“块数 ÷ 每字位数”，块号从 0 起时用整除定位字编号；
- [ ] 遇到 SPOOLing 先找“独占设备 → 逻辑共享设备”，不要把提高 CPU 利用率、并发度等间接收益当作主要目的；
- [ ] 生产者消费者 PV 操作检查：先 P 资源信号量（empty/full），后 P 互斥信号量（mutex）；
- [ ] 不发生死锁的极限资源数定理：`M ≥ n × (w - 1) + 1`，严格套用计算。
