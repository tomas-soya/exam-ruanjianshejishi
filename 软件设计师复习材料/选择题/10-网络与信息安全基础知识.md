# 第十章 网络与信息安全基础知识

## 1. 网络体系结构：OSI 七层模型 vs TCP/IP 模型与互联设备

### 体系分层与典型协议设备对照表

| OSI 七层模型 | TCP/IP 四层模型 | 核心功能与主要职责 | 典型协议 | 对应工作硬件设备 |
|---|---|---|---|---|
| **7. 应用层** | **应用层** | 提供用户网络应用接口与服务 | HTTP、FTP、SMTP、POP3、DNS、DHCP、SNMP | 应用程序、代理服务器 |
| **6. 表示层** | | 数据表示变换、数据压缩、**数据加密解密** | JPEG、ASCII、MIME、SSL/TLS | 网关 (Gateway) |
| **5. 会话层** | | 建立、管理和终止不同主机进程间的会话 | RPC、NFS、SQL | 网关 (Gateway) |
| **4. 传输层** | **传输层** | 提供**端到端（进程到进程）**的可靠/不可靠传输控制 | **TCP（面向连接、可靠）**、**UDP（无连接、不可靠）** | 网关、四层交换机 |
| **3. 网络层** | **网际层 (IP)** | 逻辑寻址、路由选择、分组转发与拥塞控制 | **IP、ICMP、IGMP、ARP、RARP**，路由协议（RIP、OSPF、BGP） | **路由器 (Router)**、三层交换机 |
| **2. 数据链路层** | **网络接口层** | 将比特组合成**帧（Frame）**，介质访问控制 (MAC)、差错控制 | HDLC、PPP、以太网 IEEE 802.3、VLAN (802.1Q) | **网桥 (Bridge)**、**二层交换机 (Switch)**、网卡 (NIC) |
| **1. 物理层** | | 透明传输原始**比特流（Bit）**，规定机械与电气特性 | RS-232、RJ-45、光纤标准 | **中继器 (Repeater)**、**集线器 (Hub)** |

### 路由协议分级分类体系
- **内部网关协议 (IGP，同一个自治系统 AS 内部)**：
  - **RIP**：基于距离矢量算法，以**跳数（Hop Count）**为度量，最大跳数限制为 15（16 为不可达），适合小型网络；
  - **OSPF**：基于链路状态算法，采用 Dijkstra 最短路径算法，收敛速度快，支持大型分层网络；
- **外部网关协议 (EGP，不同自治系统 AS 之间)**：
  - **BGP（边界网关协议）**：基于路径矢量算法，运行在 TCP 之上（端口 179），实现跨运营商跨 AS 的策略路由。

### 网络协议三要素
网络协议是网络中进行数据交换的规则与约定的集合，其三要素为：
1. **语法（Syntax）**：规定数据与控制信息的结构或格式（如数据包结构、编码方式、字段格式，解决“怎么讲”）；
2. **语义（Semantics）**：规定需要发出何种控制信息、完成何种动作及做出何种响应（如各字段的具体含义与动作控制，解决“讲什么”）；
3. **时序 / 同步（Timing）**：对事件发生顺序、通信状态转换及速度匹配的详细说明（解决“何时讲与先后次序”）。
- **避坑提示**：**时延（Delay）不是协议三要素之一**，千万不要把时延当成协议要素！

### 传输层协议核心对比：TCP vs UDP

| 对比维度 | TCP（传输控制协议） | UDP（用户数据报协议） |
|---|---|---|
| **连接状态** | **面向连接**（三次握手建立连接，四次挥手断开释放连接） | **无连接**（无需建立连接，直接发送独立数据报） |
| **可靠性** | **可靠传输**（确认应答、超时重传、滑动窗口流量控制、拥塞控制） | **不可靠传输**（尽最大努力交付，不保证数据包无差错、不丢失、不乱序） |
| **首部开销** | 首部最小 20 字节，包含序号、确认号与各种标志控制位，开销较大 | 首部固定仅 **8 字节**，**协议开销极小** |
| **控制机制** | 具备拥塞控制（慢启动、拥塞避免等）与滑动窗口流量控制 | 无拥塞控制与流量控制，传输延迟低、实时性高 |
| **二者共同特性** | **二者均提供“端口寻址”能力**（端到端进程标识、多路复用与分用）及**校验和差错检测** |
| **典型应用场景** | HTTP/HTTPS、FTP、SMTP/POP3、SSH、Telnet | DNS 查询、DHCP、SNMP、TFTP、流媒体音视频与实时通信 |

### 常见网络接入与链路层协议
- **PPPoE（Point-to-Point Protocol over Ethernet，以太网上的点对点协议）**：
  - 将 PPP 协议帧封装在以太网框架中，是用户端通过 **ADSL 宽带拨号接入 Internet 时必须安装的核心链路层协议**；
  - 允许以太网网络利用 PPP 的会话控制机制实现用户的身份认证（PAP/CHAP）、动态 IP 分配以及上网计费管理；
- **PPP（点对点协议）**：面向点对点链路（如串行线路）的数据链路层协议，支持多种网络层协议封装与链路质量监控；
- **HDLC（高级数据链路控制协议）**：面向比特的同步数据链路层协议，广泛用于广域网租用线路。

### 数据通信基础：传输方式与有效数据速率计算
- **异步通信字符帧结构**：
  - 异步传输以字符为独立传输单位，每个字符包含：**1 位起始位**、**5～8 位数据位**、**可选的 1 位奇偶校验位**以及 **1～2 位终止位**；
- **有效数据速率（Effective Data Rate）计算模型**：
  - **总传输码元速率 / 波特率**：每秒传送字符数 × 每个字符的总位数（起始位 + 数据位 + 校验位 + 终止位）；
  - **有效数据速率**：每秒传送字符数 × **每个字符的有效数据位数**；
  - **典型真题计算**：
    > **题目**：异步通信中，每个字符含 1 位起始位、7 位数据位和 2 位终止位，若每秒钟传送 500 个字符，则有效数据速率为（ ）。
    >
    > **步骤**：每个字符中有效数据位为 7 位，每秒传送 500 个字符；
    >
    > **计算**：有效数据速率 = 500 字符/秒 × 7 位/字符 = **3500 b/s**（即 3500 bit/s；总位传输速率为 500 × (1+7+2) = 5000 b/s）。

### 云计算部署模型与服务模式速查
- **云计算四大部署模型（Deployment Models，NIST 标准）**：
  1. **私有云（Private Cloud）**：**云基础设施专供某个单一客户或组织单独使用**，由该组织或第三方拥有、管理和运营，具备最高级别的数据安全性与控制权；
  2. **公有云（Public Cloud）**：云基础设施向社会公众或大型工业集团开放共享，由提供云服务的第三方组织运营管理；
  3. **社区云（Community Cloud）**：云基础设施由具有共同利益、安全合规需求或特定行业使命的若干组织联合共享使用；
  4. **混合云（Hybrid Cloud）**：由私有云、公有云等两种或两种以上不同模式组合而成，核心业务部署在私有云，扩展计算弹性部署在公有云。
- **云计算三大服务模式（Service Models）**：
  1. **IaaS（基础设施即服务）**：向用户提供物理机、虚拟机、CPU、内存、存储和网络等底层计算资源（如 AWS EC2、阿里云 ECS）；
  2. **PaaS（平台即服务）**：向开发者提供操作系统、数据库、中间件及运行开发环境，无需管理底层硬件（如 Google App Engine）；
  3. **SaaS（软件即服务）**：直接向最终用户提供完整的在线软件应用（如 Office 365、在线邮件服务、SaaS CRM）。

### 网络互联设备与应用网关核心功能对照
- **支付网关（Payment Gateway）**：部署在公共 Internet 与银行专用网络之间，负责两端数据格式转换、加密解密、身份鉴权、安全隔离与金融支付交易报文的可靠转发，是电子商务网上银行支付的核心专用网关；
- **防病毒网关**：在网络入口处对网络层和应用层流量执行集中病毒与恶意代码过滤检测；
- **出口路由器**：负责企业内外网流量的分组路由转发、路径寻址与 NAT 网络地址转换；
- **堡垒主机（Jump Server / Bastion Host）**：作为运维跳板机，提供集中的身份认证、单点登录与运维操作行为审计监控。

## 2. IP 地址分类、CIDR 无分类编址与子网划分通用计算

### IP 地址五大类别与专用私有地址范围
- **A 类**：`1.0.0.0 ～ 126.255.255.255`（最高位 `0`），默认掩码 `/8`；
  - *私有地址*：`10.0.0.0 ～ 10.255.255.255`（`10.0.0.0/8`）；
  - *特殊回环测试*：`127.0.0.0/8`（如 `127.0.0.1` 本地回环）。
- **B 类**：`128.0.0.0 ～ 191.255.255.255`（最高两位 `10`），默认掩码 `/16`；
  - *私有地址*：`172.16.0.0 ～ 172.31.255.255`（`172.16.0.0/12`）；
  - *自动专用 IP (APIPA)*：`169.254.0.0/16`（DHCP 服务器故障或无响应时主机自动获取的链路本地地址）。
- **C 类**：`192.0.0.0 ～ 223.255.255.255`（最高三位 `110`），默认掩码 `/24`；
  - *私有地址*：`192.168.0.0 ～ 192.168.255.255`（`192.168.0.0/16`）。
- **D 类**：`224.0.0.0 ～ 239.255.255.255`（最高四位 `1110`），**用于多播 / 组播（Multicast）**；
- **E 类**：`240.0.0.0 ～ 255.255.255.255`，保留用于科研实验。

### IPv6 目的地址三种基本类型体系
IPv6 数据包的目的地址划分为三种基本类型：
1. **单播地址（Unicast）**：一对一通信，数据包交付到指定单个网络接口；
2. **多播 / 组播地址（Multicast）**：一对多通信，数据包交付到属于该组的所有接口；
3. **任播 / 泛播地址（Anycast）**：一对“最近”通信，数据包交付到该地址标识的一组接口中按路由度量距离最近的一个接口；
- **极高频避坑考点**：**IPv6 取消了 IPv4 的广播地址（Broadcast）！** 原广播功能由 IPv6 多播（组播）地址完全取代。题干问“IPv6 目的地址三种基本类型中不包括”，必定选**广播**！

### 子网划分正向与逆向计算双向模型

#### 1. 正向计算模型（已知子网掩码 / 借位数求子网数与主机数）
设给定基准网络前缀为 `/n`（A 类 8、B 类 16、C 类 24），向主机位借用 k 位划分出子网：
1. **新子网掩码长度**：n' = n + k；
2. **剩余主机位数**：h = 32 - n'；
3. **可划分的子网个数**：2^k 个；
4. **每个子网可容纳的有效主机数**：
   有效主机数 = 2^h - 2 = 2^(32 - n') - 2
   （减 2 必须牢记：扣除该子网内的**网络地址**（主机位全 0）与**直接广播地址**（主机位全 1））。

#### 2. 逆向推导模型（已知主机数或子网数反求子网掩码）【高频核心考法】
- **题型 A：已知每个子网所需有效主机数 N 反求掩码**
  - **解题核心公式**：
    2^h - 2 ≥ N => 2^h ≥ N + 2
  - **标准求解三步法**：
    1. **求最小主机位数 h**：寻找满足 2^h - 2 ≥ N 的最小正整数 h（为节约地址资源、多分子网，取满足不等式的最小值）；
    2. **求新网络前缀长度 n'**：n' = 32 - h；对于默认分类网络，借位数 k = n' - n；
    3. **换算子网掩码**：前 n' 位全部置 1，后 h 位全部置 0。
  - **典型推导示例**：
    > **题目**：若 C 类地址每个子网主机数是 30 台，则子网掩码是（ ）。
    >
    > **步骤 1（确定主机位数 h）**：由 2^h - 2 ≥ 30，得 2^h ≥ 32，解得最小整数 h = 5；
    >
    > **步骤 2（确定掩码长度）**：n' = 32 - 5 = 27 位（即 `/27`，借用 C 类 24 位的后 3 位）；
    >
    > **步骤 3（计算第四字节掩码）**：高 3 位为 1，低 5 位为 0，即 11100000_2 = 128 + 64 + 32 = 224；
    >
    > **结论**：子网掩码为 **`255.255.255.224`**。

- **题型 B：已知所需划分的子网个数 M 反求掩码**
  - **解题核心公式**：
    2^k ≥ M
  - **标准求解步骤**：
    1. **求最小借位数 k**：寻找满足 2^k ≥ M 的最小正整数 k；
    2. **求新掩码长度**：n' = 默认网络前缀 + k；
    3. 换算成点分十进制子网掩码。

### CIDR 常用掩码与主机容量速查表（做题心算利器）

| 掩码前缀 | 最后一个字节二进制 | 借位数 k (相对C类) | 剩余主机位 h | 掩码最后字节十进制 | 完整子网掩码 (C类) | 每个子网最大有效主机数 (2^h - 2) |
|---|---|---:|---:|---:|---|---:|
| `/24` | `00000000` | 0 | 8 | `0` | `255.255.255.0` | 254 |
| `/25` | `10000000` | 1 | 7 | `128` | `255.255.255.128` | 126 |
| `/26` | `11000000` | 2 | 6 | `192` | `255.255.255.192` | 62 |
| **/27** | **`11100000`** | **3** | **5** | **`224`** | **`255.255.255.224`** | **30（本题典型对应）** |
| `/28` | `11110000` | 4 | 4 | `240` | `255.255.255.240` | 14 |
| `/29` | `11111000` | 5 | 3 | `248` | `255.255.255.248` | 6 |
| `/30` | `11111100` | 6 | 2 | `252` | `255.255.255.252` | 2（专用于路由器点对点链路） |

> **秒算口诀**：掩码最后字节十进制值 = 256 - 2^h。例如主机位 h=5 时，末字节直接等于 256 - 2^5 = 256 - 32 = 224。

### 子网计算与地址规划四大易错陷阱
1. **陷阱一：反推主机位时漏掉减 2**：
   - 若题目要求“每个子网 31 台主机”，切勿心算 2^5 = 32 > 31 而误选 h=5；因为扣除网络和广播后实际只有 2^5 - 2 = 30 台，无法容纳 31 台，必须取 h=6（掩码为 `/26` 即 `255.255.255.192`）。
2. **陷阱二：有效主机 IP 范围边界混淆**：
   - 子网中的第一个地址（主机位全 0）是**子网网络地址**，最后一个地址（主机位全 1）是**直接广播地址**，两者均不能分配给终端主机使用。
3. **陷阱三：混淆“子网借位数 k”与“主机位数 h”**：
   - 掩码中全 1 的代表网络号和子网号，全 0 的代表主机号；满足关系式：k + h = 32 - 默认前缀。
4. **陷阱四：路由汇聚（超网 CIDR）与子网划分方向相反**：
   - **子网划分**：借用主机位给网络位，掩码**向右变长**，网络空间划分为多个更小的子网；
   - **路由汇聚**：提取多个子网公共网络前缀，掩码**向左缩短**，将多个子网路由条目合并为一个超网路由。

## 3. 常用应用层协议、底层封装与熟知端口号速查

| 协议 | 全称 | 底层传输协议 | 默认端口号 | 核心考点与工作机制 |
|---|---|---|---|---|
| **DNS** | 域名系统 | **UDP / TCP** | **53** | 域名解析优先使用 UDP 53（开销小速度快）；区域传送使用 TCP 53；严格区分客户端解析流程与 DNS 服务器接收查询流程 |
| **DHCP** | 动态主机配置协议 | **UDP** | **67(服务器) / 68(客户端)** | 广播发现 (Discover) → 提供 (Offer) → 请求 (Request) → 确认 (ACK)；`ipconfig /release` 释放，`ipconfig /renew` 重新续租 |
| **HTTP** | 超文本传输协议 | **TCP** | **80** | 无状态短连接；明文传输 |
| **HTTPS** | 安全超文本传输协议 | **TCP** | **443** | HTTP + SSL/TLS 混合加密 |
| **FTP** | 文件传输协议 | **TCP** | **21(控制连接) / 20(数据连接)** | 双连接架构：控制连接端口 21 恒定；主动模式数据端口 20，被动模式服务器随机高位端口 |
| **SMTP** | 简单邮件传输协议 | **TCP** | **25** | **仅负责发送邮件**（客户端到邮件服务器，或邮件服务器之间传递）；结合 MIME 支持多媒体附件 |
| **POP3** | 邮局协议版本3 | **TCP** | **110** | **负责接收/下载邮件**（单向下载脱机浏览，服务器不保留状态）；加密版本 POP3S 端口 995 |
| **IMAP4** | 互联网邮件访问协议 | **TCP** | **143** | 双向同步邮件协议，客户端与服务器邮件夹状态保持一致 |
| **SNMP** | 简单网络管理协议 | **UDP** | **161(轮询Agent) / 162(Trap告警)** | 运行于 UDP 之上，Trap 是被管理设备主动向网管站上报异常事件的异步通知 |
| **Telnet** | 远程登录协议 | **TCP** | **23** | 远程明文终端会话，已被 SSH 替代 |
| **SSH** | 安全外壳协议 | **TCP** | **22** | 安全加密远程登录与 SFTP 传输 |
| **ARP** | 地址解析协议 | **网络层** | 无端口 | **IP 地址 → MAC 物理地址**；Request 采用**广播**发送，Response 采用**单播**应答 |

### DNS 域名解析全流程与查询主体决策模型（客户端 vs DNS 服务器）
- **两类查询主体的首查对象严格区分【高频必考对比】**：
  1. **客户端（本地主机/浏览器）发起解析**：
     - 查询顺序：**首先查询本机 hosts 文件** → 其次查询本机 DNS 客户端缓存 → 若均未命中，才向配置的**本地 DNS 服务器**发起查询；
     - *做题关键判据*：题干问“在浏览器输入网址后，**本地主机**将首先在（ ）查询对应 IP 地址” ⇒ 答案必选 **本机 hosts 文件**。
  2. **主域名服务器（DNS 服务器）接收到查询请求**：
     - *做题关键判据*：题干问“**主域名服务器在接收到域名请求后**，首先查询的是（ ）”（备选包含本地 hosts、转发服务器、本地缓存、授权域名服务器等） ⇒ 答案必选 **本地缓存**。DNS 服务器绝不会查询客户端的 hosts 文件，本地 hosts 文件仅供本机客户端名称解析使用。
- **递归查询 vs 迭代查询**：
  - **递归查询（Recursive Query）**：客户端向本地 DNS 服务器查询通常为递归查询，即“一问到底，必须返回最终 IP 或报错”，由被请求的服务器全权代劳后续全部查询过程；
  - **迭代查询（Iterative Query）**：本地 DNS 服务器向根/顶级/权威域名服务器查询通常为迭代查询，即“顺藤摸瓜，给下一步指路”，被请求的服务器若不能直接解析，则返回下一级 DNS 服务器地址供请求者自行继续追问。

### URL（统一资源定位符）格式组成与字段语义速查
- **标准 URL 格式构成**：
  `协议://主机名:端口号/路径/文件名`
  （典型范例：`http://www.example.com/channel/welcome.htm`）
- **核心组成字段辨析**：
  1. **协议类型（Protocol / Scheme）**：定义客户端与服务器通信所使用的网络协议规范（如 `http`、`https`、`ftp`）；
  2. **主机域名 / 服务器名称（Host / Domain Name）**：标识提供网络资源的目标服务器或主机网络节点（如 `www.example.com`）；
  3. **端口号（Port）**：Web 服务器所开放的网络服务监听端口，若使用协议默认端口（HTTP 80、HTTPS 443）通常可省略；
  4. **虚拟路径（Path）**：资源在 Web 服务器目录层次结构中的逻辑路径目录（如 `/channel/`）；
  5. **网页文件名（Filename）**：客户端请求访问的具体网页文档或资源文件名称（如 `welcome.htm`）。
- **做题高频避坑辨析**：
  - 遇到形如 `http://www.abc.com/dir/index.html` 的结构切分题，紧随协议后为“主机域名”，斜杠中间部分为“路径”，末尾带扩展名的为“网页文件名”；
  - 严格区分“主机域名/服务器名”（如 `www.example.com`）与“网页文件名”（如 `welcome.htm`）。

### Web 页面结构与 HTML/CSS 标记语言核心规范
- **HTML 页面骨架核心标记对**：
  - `<html> ... </html>`：**HTML 网页的根标记对，用于表示整个网页代码的起始和终止**；
  - `<head> ... </head>`：页面头部元信息区，包含 `<title>`、`<meta>`、`<style>`、`<link>` 等，不直接渲染在正文视图；
  - `<body> ... </body>`：页面主体内容区，包含网页中所有呈现给用户的可见元素（文本、图片、表格、超链接等）；
  - `<meta>`：元数据定义标签（如编码 `<meta charset="UTF-8">`、视口与关键字），为单标签。
- **CSS 样式表与 HTML 关联方式与禁忌**：
  - **内嵌样式**：在 HTML 文档的 `<head>` 标签内使用 `<style>` 标签定义；
  - **外部链接**：在 `<head>` 中使用 `<link rel="stylesheet" href="...">` 链接外部样式表文件；
  - **导入样式**：在 `<style>` 标签内使用 `@import url(...)` 引入；
  - **内联样式**：在 HTML 具体标签元素上通过 `style="..."` 属性定义；
  - **做题禁忌**：`<!-- -->` 是 HTML 注释标记，浏览器忽略其内容，**绝对不能在 `<!-- -->` 中定义样式**。

### 远程登录控制协议辨析与 IGMP 组播协议
- **可用于远程登录或控制的典型协议**：
  - **SSH（Secure Shell，TCP 22）**：安全加密远程终端登录与命令执行协议；
  - **Telnet（TCP 23）**：传统明文远程字符终端协议；
  - **RFB（Remote Frame Buffer）**：VNC 图形桌面控制所采用的远程帧缓冲协议；
  - **RDP（Remote Desktop Protocol，TCP 3389）**：微软 Windows 远程桌面协议；
- **做题高频辨析（IGMP）**：
  - **IGMP（Internet 组管理协议）**：工作在**网络层**，用于主机向本地组播路由器报告和维护**多播/组播（Multicast）组成员关系**，**绝对不能用于远程登录或远程控制**！

## 4. 常见网络诊断命令与故障排查工具速查

| 命令名称 | 所属主要协议/层级 | 核心功能与工作机制 | 常用参数与做题速记 |
|---|---|---|---|
| **ping** | **网络层（ICMP 协议）** | 向目标主机发送 ICMP Echo Request（回显请求）报文并等待回显应答，**用于测试两台主机之间的双向网络连通性及往返延迟（RTT）** | `ping 目标IP/域名`；排查次序：`ping 127.0.0.1`（测本机TCP/IP协议栈）→ `ping 本机IP` → `ping 网关IP` → `ping 外部服务器IP` |
| **tracert** (Win)<br>**traceroute** (Linux) | **网络层（ICMP / UDP）** | 通过逐次递增 IP 数据包的 TTL（生存时间）值，**探测并记录数据包到达目的主机所经过的每一个路由器（跳数）及往返时延**，用于定位网络路径故障节点 | 题干问“跟踪路由”、“探测经过的网关节点与路径故障”直接选 `tracert` |
| **ipconfig** (Win)<br>**ifconfig** (Linux) | **网络管理与配置工具** | 查看、配置和释放主机的网络适配器 IP 地址、子网掩码、默认网关、DNS 服务器及物理 MAC 地址 | • `ipconfig`：查看基本 IP 配置<br>• `ipconfig /all`：查看**完整网络配置（包括 DHCP 是否启用、物理地址、DNS、租约时间等）**<br>• `ipconfig /release`：**主动释放当前主机自动获取的 DHCP IP 地址**<br>• `ipconfig /renew`：重新向 DHCP 服务器申请获取/续订 IP 地址<br>• `ipconfig /flushdns`：**清除（刷新）本地 DNS 解析器缓存** |
| **netstat** | **传输层与网络状态监控** | 监控和显示当前系统的 **TCP/IP 网络活动连接、正在监听的端口（Listening Ports）以及以太网统计数据** | • `netstat -a`：显示所有活动的连接和正在监听的 TCP/UDP 端口<br>• `netstat -n`：以数字形式（IP:端口）显示地址和端口号，加快显示速度<br>• `netstat -o`：显示每个连接关联的**所属进程 ID（PID）**<br>• **做题高频组合**：`netstat -ano` 用于在 Windows 下**排查端口占用、定位某个网络开放端口对应的应用程序/进程** |
| **nslookup** | **应用层（DNS 协议）** | 查询 DNS 域名解析结果、查询特定域名服务器记录、**诊断与测试 DNS 域名系统解析故障** | 交互式与非交互式查询；排查“域名无法访问是否由于 DNS 解析故障引起”首选 `nslookup` |
| **arp** | **网络层（ARP 协议）** | 查看和修改本地的 ARP 高速缓存表（IP 地址与物理 MAC 地址的动态/静态映射条目） | • `arp -a`：**显示当前所有网卡的 ARP 缓存表项**（查看已知 IP 对应的 MAC 地址）<br>• `arp -d`：清除 ARP 缓存条目 |

- **网络排错高频易错辨析清单**：
  1. **诊断 DNS 故障工具**：`nslookup`（专门查询 DNS）、`ping`（通过测试域名能否解析出 IP 并连通）；而 `netstat` 用于查看本地端口和连接状态，**不能用于诊断 DNS 域名解析故障**；
  2. **释放与更新 IP 租约**：`ipconfig /release`（释放）、`ipconfig /renew`（续约）；
  3. **清除本地 DNS 缓存**：`ipconfig /flushdns`；
  4. **端口占用与进程排查**：在命令行查看某端口被哪个程序占用，使用 `netstat -ano`（或结合 `tasklist` 按 PID 查进程）。

## 5. 信息安全体系：安全属性、网络防御与常见攻防手段

### 信息安全五大基本属性
1. **机密性 (Confidentiality)**：确保信息不暴露给未授权的实体（防窃听，对策：**加密**）；
2. **完整性 (Integrity)**：确保信息在传输和存储中**未经授权不可被改变、篡改或伪造**（对策：**散列函数、数字签名、消息认证码 MAC**）；
3. **可用性 (Availability)**：确保得到授权的实体在需要时可以正常访问和使用资源（防拒绝服务，对策：**负载均衡、冗余灾备**）；
4. **真实性 / 不可抵赖性 (Non-repudiation)**：确保行为人无法否认自己所发出的行为或消息（对策：**数字签名、审计追踪**）；
5. **可控制性 (Controllability)**：对信息的传播及内容具有控制能力（对策：**访问控制、授权**）。

### 常见网络攻击手段与防范对策
- **计算机病毒（Computer Virus）核心特性与分类**：
  - **五大核心基本特征**：**传染性**（能将自身代码嵌入其他宿主程序自我复制）、**隐蔽性**（短小伪装，不易被普通用户察觉）、**潜伏性**（长期潜伏在系统中待特定条件满足才发作）、**破坏性**（消耗系统资源、降低效率、破坏文件或导致瘫痪）、**触发性**（预设触发条件如特定日期、特定操作执行）；
  - **做题高频避坑陷阱**：**计算机病毒不具有“自毁性”**！做题若问“计算机病毒的特征不包括”，首选**自毁性**；
  - **常见病毒前缀命名规范**：
    - `Trojan`：特洛伊木马病毒（不具传染性，通过伪装诱骗用户执行，窃取数据或留后门）；
    - `Worm`：蠕虫病毒（利用网络漏洞主动自主传播感染，如冲击波、震荡波、永恒之蓝）；
    - `Macro`：宏病毒（寄生在 Office 文档或模板中）；
    - `Script`：脚本病毒（利用 VBS、JS 等脚本编写）；
    - `Win32/W32`：Windows 系统平台病毒。
- **拒绝服务攻击 (DoS / DDoS)**：利用大量伪造请求（如 SYN Flood 耗尽半开连接队列）耗尽服务器计算或带宽资源；
- **重放攻击 (Replay Attack)**：拦截合法报文并原样重发欺骗系统；对策：**加入时间戳 (Timestamp) 或随机数 (Nonce)**；
- **中间人攻击 (MITM)**：窃听通信并篡改数据，伪装成双方；对策：**通过 CA 数字证书认证身份与公钥**；
- **SQL 注入攻击**：在用户输入中注入恶意 SQL 片段破坏原意；对策：**参数化预编译查询（Prepared Statement）、严格输入校验与最小数据库权限**；
- **跨站脚本攻击 (XSS)**：在网页中注入恶意脚本窃取 Cookie；对策：**HTML 实体转义、配置 HttpOnly Cookie 属性**；
- **恶意勒索病毒与漏洞利用（WannaCry 永恒之蓝）**：
  - **利用协议**：利用 Windows 的 **SMB 协议（Server Message Block，服务器消息块协议，端口 TCP 445）** 漏洞（MS17-010）；
  - **攻击机制**：利用 SMB 漏洞直接获取目标主机的系统最高权限（SYSTEM 权限），在内网局域网主动横向蔓延传播并加密磁盘文件勒索；
  - **选项辨析**：SSH（TCP 22 远程安全终端）；HTTP（TCP 80 Web 传输）；TCP（传输层协议，漏洞位于应用层的 SMB 协议实现中而非泛指 TCP 本身）。
- **数据库窃取与凭证攻击四步链（拖库、洗库、撞库、社工库）核心辨析**：
  - **拖库（脱库，Dump DB）**：黑客通过 SQL 注入、系统漏洞或越权访问等手段，**非法导出并获取目标系统数据库的全部/整个用户资料信息**；
  - **洗库（Clean & Filter）**：黑客对拖库获取的海量原始数据进行清洗、筛选、解密和分类梳理，提炼出高价值账户（如金融凭据、管理员账号）进行变现；
  - **撞库（Credential Stuffing）**：黑客利用已泄露的“用户名—密码”字典，**去其他网站或平台批量尝试登录**（利用网民在多平台复用相同账号密码的习惯）；
  - **社工库（Social Engineering DB）**：黑客将长期从各个渠道拖库、洗库得到的个人隐私数据聚合建库，通过社会工程学手段进行深度关联查询与精准利用。

### 网络防御技术：防火墙、DMZ、WAF 与 IDS/IPS
- **防火墙（Firewall 核心考法）**：
  - **部署位置与职能**：部署在**企业内部网与外部网之间**，用来**检查网络进出的所有请求分组是否合法，允许合法流量通过并拦截非法请求，保护内部网络资源不被非法使用**；
  - **防御技术横向对比**：
    - **防火墙**：网络边界的“守门人”，主动依据规则审查分组并控制网络访问权限；
    - **入侵检测（IDS）**：旁路被动监听网络流量，发现入侵行为仅告警记录，不直接在边界阻断数据流；
    - **网络地址转换（NAT）**：私网 IP 与公网 IP 互相映射，解决 IP 短缺并隐藏内部网络结构，不具备请求分合法性检查的安全功能；
    - **防病毒（Antivirus）**：终端系统上的恶意代码查杀，保护计算机主机文件与操作系统安全，而非网络边界的分组检查控制。
- **包过滤防火墙**：工作在网络层和传输层，根据五元组（源IP、源端口、目的IP、目的端口、协议）执行访问控制列表 ACL；
- **DMZ（非军事化隔离区）**：在内外网之间设立的缓冲隔离区。**DMZ 内放置面向公网提供服务的服务器（Web、邮件、DNS 等）**，核心数据库必须存放在内网；
- **Web 应用防火墙 (WAF)**：工作在应用层（第七层），专门防范针对 Web 漏洞（SQL注入、XSS、跨站请求伪造 CSRF）的攻击；
- **入侵检测系统 (IDS)**：**旁路被动监听**网络流量，发现入侵行为后产生报警日志，不阻断网络；
- **入侵防御系统 (IPS)**：**串行串联在线接入**网络链路中，发现攻击流量立即实时阻断并丢弃数据包。

### 网络与系统安全防护分层体系
- **网络信息安全层次化防御体系**：
  1. **物理安全**：设备防雷击、防静电、机房门禁管理、防水防火与温湿度环境控制；
  2. **网络安全**：边界防火墙、入侵检测与防御系统（IDS/IPS）、VPN 隧道、网络流量控制与访问控制列表（ACL）；
  3. **系统安全**：**漏洞发现与补丁管理（针对操作系统与服务器软件的漏洞修补）**、操作系统权限最小化、强身份认证与系统安全审计；
  4. **应用与数据安全**：应用系统防 SQL 注入/XSS 攻击、数据存储与传输加密、数字签名与防篡改。
- **做题典型归属判定**：
  - “漏洞发现与补丁管理”属于**系统安全需求**的核心应对措施；
  - “设备防雷击”属于**物理安全需求**；
  - “入侵检测”、“流量控制”属于**网络安全需求**。
- **网络内防内控管理核心策略**：
  - 针对企业内部网络安全管理，“加强内防内控”旨在防范内部人员越权、滥用权限或违规操作带来的安全隐患；
  - **核心策略包括**：
    1. **终端访问授权**：严格细粒度权限控制，防止合法终端用户越权访问未授权资源；
    2. **加强终端安全检查与策略管理**：定期对终端进行防病毒软件安装核验、补丁强制更新与安全基线检查；
    3. **加强员工上网行为管理与违规审计**：对内部网络流量、访问记录与外联行为进行审计追溯；
  - **做题避坑辨析**：**单纯控制终端接入数量不属于内防内控的有效策略**（合法接入的终端若未授权或缺乏安全基线同样构成威胁，控制数量是网络容量规划而非安全管控措施）。

## 6. 现代密码体系、数字证书认证链与分层安全协议

### 对称加密 vs 非对称加密体系全方位对比

| 对比维度 | 对称密钥加密体制（私钥密码） | 非对称密钥加密体制（公钥密码） |
|---|---|---|
| **密钥特点** | 加密密钥与解密密钥**完全相同**（或极易相互推导） | 加密密钥（公钥）与解密密钥（私钥）**成对出现且数学分离** |
| **加解密速度** | **计算速度极快，算法硬件实现简单** | **计算复杂度极高，加解密速度慢（慢数百至数千倍）** |
| **适用场景** | 适合对**大批量、海量业务明文数据**进行实时流式或块加密 | 适合对**少量数据**加密、**对称密钥的安全分发分发协商**及**数字签名** |
| **密钥管理规模** | n 个通信实体两两保密通信需要 `n(n - 1) / 2` 个密钥，密钥数量随节点剧增 | 每个实体仅需一对公私钥，全网 n 个实体只需 `2n` 个密钥 |
| **经典代表算法** | **DES（56位）、3DES（112/168位）、AES（128/192/256位）、RC4（流密码）、IDEA**、国密 SM4 | **RSA（大数质因数分解困难性）、ECC（椭圆曲线离散对数困难性）、ElGamal**、国密 SM2 |

### 混合加密体制与数字签名工作机制
1. **混合加密体制工作流程**：
   - 发送方随机生成一个临时、一次性的**对称会话密钥（Session Key）**；
   - 用该对称密钥对大体积的**明文正文数据进行高速加密**；
   - 用接收方的**公开公钥**对该会话密钥进行非对称加密（称为数字信封）；
   - 将加密正文与数字信封一并发送给接收方；
   - 接收方先用自己的**私钥**解开数字信封取得对称会话密钥，再用该对称密钥解密正文。
2. **数字签名验证数学模型**：
   - 发送方对原始消息 M 计算单向散列摘要：`Digest = Hash(M)`；
   - 发送方使用自己的**私钥（Private Key）**对摘要进行加密生成签名：`Signature = Encrypt(Digest, Private_Sender)`；
   - 接收方收到消息 M 与签名后：
     - 用发送方的**公钥（Public Key）**解密签名：`Digest' = Decrypt(Signature, Public_Sender)`；
     - 对收到的消息 M 重新计算摘要：`Digest_calc = Hash(M)`；
     - 比较：`Digest_calc ≟ Digest'`。若相等，证明消息未被篡改且确由发送方发出（防抵赖）。

### CA 数字证书认证链机制
- **解决的核心信任危机**：防止中间人伪造篡改公开公钥（即冒充合法通信方发布假公钥）；
- **数字证书内容**：包含证书持有者的名称、公钥、有效期、签发机构（CA）名称及序列号等；
- **CA 签名过程**：CA 机构使用 **CA 自身的私钥** 对上述全部证书内容计算出的摘要进行数字签名，生成最终证书；
- **客户端验签过程**：所有浏览器或客户端操作系统均内置受信任根 CA 的**公开公钥**。客户端使用 **CA 的公钥** 对证书上的签名进行验证：`Verify(Certificate, Public_CA)`。验签通过后，即可确信证书内包含的用户公钥是真实合法的。

### 分层安全协议全景对比
1. **网络层安全：IPSec 协议簇**：
   - **AH 协议（认证头，Authentication Header）**：提供数据源身份认证、数据完整性检查和防重放保护；**AH 协议不提供数据加密功能（无保密性）**！
   - **ESP 协议（封装安全载荷，Encapsulating Security Payload）**：**既提供数据加密保密性**，又提供数据源身份认证、完整性检查与防重放保护；
   - **工作模式**：
     - *传输模式（Transport Mode）*：仅对 IP 数据包的有效载荷（传输层及以上）进行保护，保留原 IP 头部，适合主机到主机通信；
     - *隧道模式（Tunnel Mode）*：对整个原始 IP 数据包（含原 IP 头部）进行封装加密，并添加新的外部 IP 头，专用于 VPN 网关到网关的站点间安全隧道。
2. **传输层安全：SSL / TLS**：
   - 工作在 TCP 之上、应用层之下，为 HTTP、FTP、SMTP 提供通用的端到端加密与完整性保护；
   - HTTPS 协议默认运行于 TCP **443** 端口。
3. **应用层安全：PGP / S/MIME**：
   - PGP（Pretty Good Privacy）是一套基于混合加密的电子邮件安全传输软件，综合使用 RSA/IDEA 算法对邮件正文进行数字签名与加密压缩。

## 7. 高频网络服务协议工作机制（DNS/DHCP）与常用端口速查

### DNS 递归查询 vs 迭代查询工作流程
- **递归查询（Recursive Query）**：
  - “一路问到底，代劳返回最终结果”；
  - 客户端向本地 DNS 服务器发出递归查询请求，本地 DNS 服务器若不知道答案，必须以自己的身份代表客户端向其他服务器进一步查询，直到取得最终 IP 并返回给客户端；客户端只需等待最终答案。
- **迭代查询（Iterative Query）**：
  - “问路指引，自己挨个打听”；
  - 本地 DNS 服务器向根 DNS、顶级域名 DNS、权威 DNS 服务器查询时，上级服务器如果不知道具体解析结果，不会替其递归追查，而是**返回下一级 DNS 服务器的 IP 地址**，由本地 DNS 服务器自行向下一级服务器重新发起迭代请求。

### DHCP 动态主机配置协议四步广播租约
DHCP 客户端从局域网 DHCP 服务器获取 IP 地址、子网掩码、网关和 DNS 服务器地址时，按序经历以下 4 个阶段（全部基于 UDP 广播）：
1. **DHCP Discover（发现阶段）**：客户端以广播形式发送 Discover 报文（源 IP `0.0.0.0`，目的 IP `255.255.255.255`，端口 67），寻找网络中的 DHCP 服务器；
2. **DHCP Offer（提供阶段）**：网络中接收到的各 DHCP 服务器分别从地址池中挑选一个尚未分配的 IP，以广播形式响应 Offer 报文（包含推荐的 IP、租约期限等）；
3. **DHCP Request（选择阶段）**：客户端通常接受第一个收到的 Offer 报文，并再次以广播形式发出 Request 报文，向全网声明自己选择接受该服务器的 IP 地址；
4. **DHCP Acknowledge（确认阶段）**：被选中的 DHCP 服务器向客户端广播发送 Ack 确认报文，正式将该 IP 租借给客户端使用，租约生效。

## 8. 第十章核心易错陷阱防坑指南与做题检查清单

### 核心易错陷阱防坑指南
1. **计算子网可用主机数忘记减 2**：
   - **陷阱**：计算 `/26` 的可用主机数时直接算 `2^6 = 64`；
   - **避坑法宝**：主机位全 0 是网络地址，主机位全 1 是广播地址，**可用主机数必须严格减 2**（`2^h - 2 = 64 - 2 = 62`）。
2. **数字签名与公钥加密密钥颠倒**：
   - **陷阱**：把“发送方公钥”拿来做数字签名；
   - **避坑法宝**：**公钥加密防偷看（仅私钥能解密），私钥签名防赖账（所有人用公钥验真）**！发信方绝对只能用**自己的私钥签名**。
3. **AH 协议保密性误区**：
   - **陷阱**：认为 IPSec 中的 AH 协议可以防止窃听；
   - **避坑法宝**：**AH 协议只认证不加密**，报文完全以明文在网络中传输；需要加密保密性必须采用 **ESP 协议**。
4. **DNS 递归与迭代角色颠倒**：
   - **陷阱**：误以为根域名服务器替本地 DNS 服务器进行递归追问；
   - **避坑法宝**：根域名服务器只进行迭代查询，直接返回下一级顶级域名服务器的 IP，绝不替本地 DNS 递归打听。

### 第十章做题自检检查清单
- [ ] 分层题先找唯一动作：压缩/加密是表示层，可靠帧传输是数据链路层，端到端可靠通信是传输层；
- [ ] 端口题同时记“协议—传输层—端口”：SNMP/UDP/161、SMTP/TCP/25、POP3/TCP/110、FTP 控制/21、HTTPS/TCP/443、DNS/UDP/53；
- [ ] 路由题先分 AS 内或 AS 间，再在候选中选 RIP/OSPF 或 BGP；地址匹配遵循最长前缀；
- [ ] 安全题先确定要保护的属性（机密性、完整性、可用性），再判断控制措施是否真的覆盖该层次；
- [ ] 区分主机特权状态与进程状态，网络协议安全应分清应用层加密与传输层/网络层加密；
- [ ] 子网反求掩码题先区分“已知主机数”还是“已知子网数”：主机数用 2^h - 2 ≥ N 求最小 h；掩码末字节直接套用 256 - 2^h；
- [ ] CA 证书核对：证书内是用户公钥，签名是 CA 的私钥签名，客户端用 CA 的公钥验签。
