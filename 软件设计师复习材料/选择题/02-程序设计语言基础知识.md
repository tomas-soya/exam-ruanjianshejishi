# 第二章 程序设计语言基础知识

## 1. 参数传递机制：传值调用 vs 传引用调用

### 核心机制对比

| 传递方式 | 实参与形参关系 | 形参修改是否回写实参 | 典型场景与底层实现 |
|---|---|---|---|
| **传值调用（Call by Value）** | 形参开辟独立存储单元，接收**实参值的副本** | **否**。函数内对形参的任何修改均不影响实参 | C 语言普通变量传参、Java 基本数据类型传参 |
| **传引用调用（Call by Reference）** | 形参不开辟独立数值单元，直接作为**实参的别名（地址引用）** | **是**。函数内对形参的修改直接反映在实参上 | C++ 引用传参（`&x`）、Pascal 的 `var` 传参 |

### 混合传参执行跟踪三步法
1. **形实映射绑定**：在调用函数前，先写出每一个形参变量是“值复制”还是“引用绑定实参”；
2. **函数体逐步计算**：在函数内部按语句次序计算，区分局部临时变量与形参；
3. **调用方状态回写**：函数返回后，**只有被引用绑定的实参**的值会被改写，传值实参保持调用前的值不变。

## 2. 编程语言范式与特性：编译型 vs 解释型

### 编译型语言 vs 解释型语言
- **编译型语言（如 C/C++）**：
  - 由编译器一次性将源程序全部翻译为机器代码/目标代码，再由硬件直接执行；
  - **特点**：执行效率高，具备底层指针操作与直接内存访问能力，**最适合开发底层系统级软件（如操作系统内核、设备驱动、嵌入式系统）**；但生成的目标代码强依赖于特定硬件与操作系统，**跨平台移植性较差**。
- **解释型语言（如 Python、JavaScript）**：
  - 由解释器逐句翻译源程序并立即由解释器执行，不生成独立的目标机器代码；
  - **特点**：**跨平台可移植性好**、动态灵活性高，但由于运行期边翻译边执行，**运行效率相对较低**。
- **混合型语言（如 Java）**：
  - 先静态编译生成与机器无关的字节码（`.class`），再由 Java 虚拟机（JVM）解释执行；JVM 中的 **JIT（即时编译器）** 会在运行期将热点字节码动态编译为本地机器码并优化，兼顾可移植性与执行速度。

### 常见编程语言分类体系与编程范式速查
- **常见编程语言分类与范式速查**：
  - **函数式语言（Functional）**：将计算过程视为数学上的函数求值，避免使用程序状态以及可变对象，代表语言：**Lisp**、Haskell、Erlang；
  - **逻辑式语言（Logical）**：建立在形式逻辑推理基础之上，由事实与规则构成，代表语言：**Prolog**；
  - **面向对象语言（Object-Oriented）**：支持类、封装、继承与多态，代表语言：Java、C++、Smalltalk；
  - **命令式 / 过程式语言（Imperative / Procedural）**：关注计算执行步骤与内存状态演变，代表语言：C、Pascal、Fortran；
  - **脚本语言（Scripting）**：通常采用解释方式执行，语法动态灵活，**同样具备变量、数据结构与函数**（做题高频避坑：绝不能认为脚本语言中不使用变量和函数！），代表语言：Python、JavaScript、PHP、Shell；
  - **标记语言（Markup）**：专门用于描述文本格式化排版、内容结构与超链接关联，不具备通用算法计算能力，代表语言：HTML、XML。
- **CSS 样式表与 HTML 网页关联方式速查**：
  - **内嵌样式**：在 HTML 文档的 `<head>` 标签内使用 `<style>` 标签定义；
  - **外部链接样式**：在 `<head>` 中使用 `<link>` 标签链接外部 `.css` 样式表文件；
  - **导入样式**：在 `<style>` 标签内使用 `@import` 引入样式表文件；
  - **内联样式（行内样式）**：在具体 HTML 标签内使用 `style` 属性直接定义；
  - **做题高频避坑**：`<!-- -->` 是 HTML 的**注释标记**，浏览器完全忽略注释中的内容，**绝对不能在 `<!-- -->` 内部定义生效的 CSS 样式**！
- **程序设计语言基本成分体系（数据、运算、控制与传输）**：
  - 通用高级程序设计语言通常提供四类基本成分：
    1. **数据成分**：常量、变量、全局/局部变量、基本类型与复合数据类型；
    2. **运算成分**：算术运算、关系运算、逻辑运算与位运算；
    3. **控制成分**：规定程序各成分的执行顺序，由**顺序结构、选择结构（分支结构）、循环结构**三大基本结构组成；
    4. **传输成分**：输入输出（I/O）、参数传递与变量赋值。

### Python 关键语法特征与易错点
- **动态解释型**：支持面向对象、动态类型、跨平台与丰富的标准库；
- **Python 包管理工具（pip）标准命令**：使用 `pip install <包名>` 安装第三方模块（例如安装 numpy 模块的标准命令为 `pip install numpy`，更新使用 `pip install --upgrade`，卸载使用 `pip uninstall`）；
- **列表操作**：
  - `list.append(obj)`：将传入的整个对象作为**一个单独元素**追加到列表末尾（例如 `[1,2].append([3,4])` 结果为 `[1, 2, [3, 4]]`）；
  - `list.extend(iterable)`：将可迭代对象中的元素**逐个解包并扩展**追加到列表末尾（结果为 `[1, 2, 3, 4]`）；
  - **列表切片与切片原地修改**：切片语法 `lst[start:stop]` 采用左闭右开区间 `[start, stop)`（不包含下标 `stop` 处的元素）。切片赋值 `lst[start:stop] = new_list` 会原地替换该区间的所有元素；若赋值为空列表（如 `lst[1:4] = []`），则表示**原地切除并删除**下标从 1 到 3 的连续元素，原列表保留首尾未切除元素（例如 `lst = [1, 2, 3, 4, 5]` 执行 `lst[1:4] = []` 后结果为 `[1, 5]`，绝不是取子切片 `[2, 3, 4]`）。
- **异常处理语法**：Python 使用 `try...except...else...finally` 结构，**绝对没有 Java 的 `catch` 关键字**！
- **对象标识与等价性判断（`is` vs `==`）**：
  - `is`：**判断两个对象的内存地址是否相同**（即是否指向同一物理对象，底层比较 `id(a) == id(b)`）；
  - `==`：**判断两个对象的值是否相等**（内容等价性，底层调用对象的 `__eq__()` 方法进行取值比较）；
  - **避坑提示**：小整数池范围内的整数可能因解释器优化而复用同一内存地址，但 `is` 和 `==` 概念完全独立，数字类型同样可以使用 `is` 比较对象同一性，绝不能说“数字不能用 `is`”，也不能认为两者等价。

### 运行时内存组织：栈（Stack）vs 堆（Heap）
- **栈区（Stack）**：由编译器/运行环境自动分配和释放。存放函数调用活动记录（栈帧）、局部基本类型变量、对象引用指针；在函数调用和返回时由系统进行控制和管理，分配连续、速度极快；
- **堆区（Heap）**：由程序员在程序中根据需要动态申请或由运行环境动态管理（如 `new` 创建对象、用户自由释放或由垃圾回收 GC 回收）。存放所有类实例和动态数组对象；空间灵活但速度相对较慢。

## 3. 乔姆斯基（Chomsky）形式文法层次体系

文法 G = (V_N, V_T, P, S)，根据产生式 α → β 的形式约束，分为 4 个层级：

| 文法类型 | 文法名称 | 产生式规则特征 | 识别自动机 | 典型应用 |
|---|---|---|---|---|
| **0 型文法** | 短语文法 | 无限制（α 至少含一个非终结符） | 图灵机（TM） | 可计算性理论 |
| **1 型文法** | 上下文有关文法 (CSG) | 产生式长度满足 \|α\| ≤ \|β\|（形式为 α A β → α γ β） | 线性有界自动机 (LBA) | 自然语言理解 |
| **2 型文法** | **上下文无关文法 (CFG)** | **A → β**（左部仅为单个非终结符） | **下推自动机 (PDA)** | **绝大多数通用程序语言的语法结构** |
| **3 型文法** | **正规文法 (RG)** | A → aB 或 A → a（右线性/左线性） | **有限自动机 (FA: DFA/NFA)** | **词法记号（Token）的定义与识别** |

### 文法推导与语言判别通用方法
1. **产生式推导**：从文法开始符 S 出发，用产生式右部替换左部非终结符，直至全为终结符；
2. **终结符约束**：推导出的最终合法句子中，**绝对不能出现产生式未定义的终结符**；
3. **结构模式提取**：通过列举推导最短的几个句子（如推导长度为 1, 2, 3 的串），总结其数学规律（如 0 和 1 的个数关系、前缀/后缀模式）。

## 4. 表达式表示法与语法树遍历

中缀表达式（人类习惯）、前缀表达式（波兰式）、后缀表达式（逆波兰式，计算机与虚拟机计算最常用）：

### 中缀转后缀的两大通用解法
1. **二叉语法树遍历法**：
   - 将表达式构造为二叉语法树：**操作数均为叶子节点，运算符均为内部（分支）节点**；
   - **前缀式（波兰式）**：对语法树进行**前序遍历**（根 → 左 → 右）；
   - **中缀式**：对语法树进行**中序遍历**（左 → 根 → 右，注意运算符结合性与括号）；
   - **后缀式（逆波兰式）**：对语法树进行**后序遍历**（左 → 右 → 根）。
2. **加括号极速转换法（考场做题首选）**：
   - 步骤一：严格按运算符优先级和结合性，给表达式中所有子运算**全部加上括号**；
   - 步骤二：将每个括号内的**运算符移动到该括号对应的右括号之后**；
   - 步骤三：擦掉所有括号，剩余序列即为标准后缀表达式！
   - *示例*：x * (5 + y) / a - b
     - 加括号：((((x * (5 + y))) / a) - b)
     - 移符号：((((x (5 y)+)*) a)/ b)-
     - 去括号：`x 5 y + * a / b -`

### 逻辑表达式短路求值规则与判定
- **短路求值（Short-circuit Evaluation）原理**：在逻辑表达式求值过程中，根据逻辑运算符的定义，若仅凭前面已计算出的子表达式结果就足以唯一确定整个表达式的值，则**直接停止剩余子表达式的计算（发生短路）**。
- **两大核心逻辑运算符短路规则**：
  1. **逻辑与（`&&` / `and`，全真才真）**：
     - 对于表达式 `A && B`，**若 `A` 的值为假（0 / False），则整个表达式的值必定为假**，无需继续计算 `B` 的值；
     - 只有当 `A` 的值为真时，才需要继续计算 `B` 的值来决定最终结果。
  2. **逻辑或（`||` / `or`，一真即真）**：
     - 对于表达式 `A || B`，**若 `A` 的值为真（1 / True），则整个表达式的值必定为真**，无需继续计算 `B` 的值；
     - 只有当 `A` 的值为假时，才需要继续计算 `B` 的值来决定最终结果。
- **复合表达式典型题型实战判定**：
  - **题型 1（与运算短路）**：对表达式 `x && (y || !z)` 进行短路求值时，若 `x` 为假，则整个表达式的值直接确定为假，**无需计算 `y` 和 `z` 的值**；
  - **题型 2（或运算短路）**：对表达式 `a or ((c < d) and b)` 进行短路求值时，若 `a` 为真（True），根据或运算规则整个表达式的值直接确定为真，**无需计算后续括号内的 `((c < d) and b)`**。

## 5. 有限自动机（FA）与正规表达式

### DFA 与 NFA 的本质区别与不确定性判定
- **确定性有限自动机（DFA）**：对于任意状态，输入一个字符，有且仅有一个确定的后继转换状态；且**绝对不存在 ε（空串）弧**；
- **非确定性有限自动机（NFA）**：
  - **NFA 的“不确定性”严格表现为以下两点**：
    1. **存在标记为 ε 的状态转移（空转移）**：无需输入任何字符即可从一个状态跳转到另一个状态，导致同一时刻自动机可能处于多个不同状态；
    2. **同一状态下对同一字符可以有多个下一状态转移**：状态转移函数是一对多的映射关系。
  - **经典避坑陷阱（终态数量判定）**：
    - **DFA 和 NFA 都可以有多个终态（Accepting States）**！
    - 终态集合 F ⊆ S 是自动机合法停机接收的标志，有多个终态只是表示可以接受多种不同结尾条件的语言串，**存在多个终态绝不属于 NFA 的不确定性表现**（做题时若问“NFA 不确定性表现为哪些”，千万不要选“存在多个终态”！）。

### 自动机识别串的检验方法
1. **路径通达性**：从初态出发，沿着输入串中的每个字符依次寻找转移路径，若串读完时停留在**终态（双圈标记）**，则该串被识别；
2. **前缀/后缀特征分析**：
   - 若所有通向终态的弧上标记为 `101`，则被识别的串**必须以 101 结尾**；
   - 若初态自环为 `a`，离开初态必须通过 `b`，则被识别的串必须满足 `a*b...` 结构。

## 6. 编译全流程核心阶段与错误处理体系

### 编译各阶段分工与输出产物

| 阶段 | 输入对象 | 主要任务 | 核心理论/工具 | 输出产物 |
|---|---|---|---|---|
| **1. 词法分析** | 源程序字符流 | 扫描字符流，识别关键字、标识符、常数、运算符等词法记号（Token） | 正规文法、有限自动机 (DFA/NFA) | 记号流 (Token 流) |
| **2. 语法分析** | Token 流 | 将 Token 组合成语句、表达式等语法短语，检查程序**结构/形式是否符合文法** | 上下文无关文法 (CFG)、递归下降/LL(1)/LR | 抽象语法树 (AST) 或语法分析树 |
| **3. 语义分析** | 语法树 | 进行类型检查、类型转换、声明与引用一致性检查；**语法制导翻译**（计算属性文法） | 属性文法、静态语义检查 | 带属性的语法树 |
| **4. 中间代码生成** | 带属性语法树 | 生成独立于具体机器指令的中间代码；便于代码优化和跨平台移植 | 三地址码、四元式、逆波兰式、树 | 中间代码 (IR) |
| **5. 代码优化** | 中间代码 | 对中间代码进行等价变换（公共子表达式消除、循环展开、死代码消除等），提高时空效率 | 基本块分析、控制流图 | 优化后的中间代码 |
| **6. 目标代码生成** | 优化后中间代码 | 将中间代码转换为特定机器的机器指令或汇编代码，分配物理寄存器与内存地址 | 强依赖于目标机器硬件架构 | 目标机器代码 |

### 源代码到可执行程序的构建四大阶段
C/C++ 等编译型高级语言从源代码到最终生成机器可执行文件，必须依次经历以下四个核心阶段：
1. **预处理（Preprocessing）**：由预处理器处理源文件中的预处理伪指令（如 `#include` 头文件包含展开、`#define` 宏替换展开、`#ifdef` 条件编译等），滤除注释，生成纯 C 语言预处理文本文件（如 `.i` 文件）；
2. **编译（Compilation）**：由编译器对预处理后的源文件进行词法分析、语法分析、语义分析及中间代码生成与优化，最终将高级语言翻译为等价的**汇编语言程序**（如 `.s` 文件）；
3. **汇编（Assembly）**：由汇编器将汇编语言代码转换为机器指令，生成**可重定位的目标文件**（如 `.o` 或 `.obj` 格式的机器码文件）；
4. **链接（Linking）**：由链接器将多个目标文件以及所依赖的系统/第三方库文件进行打包合并，解决外部符号引用并重定位物理内存地址，最终生成可由操作系统直接加载运行的**可执行程序**（如 Windows 的 `.exe` 或 Linux 的 ELF 文件）。
- **流程记忆口诀**：**预处理 → 编译 → 汇编 → 链接**（顺序不可颠倒）。

### 贯穿全程的两个核心机制
- **语法制导翻译与语义分析的目标**：
  - 编译器的语义分析常采用**语法制导翻译**的方法，它属于编译期的**静态语义分析**方法；
  - 对包含变量的表达式，其核心处理目标是进行静态类型相容性检查与类型转换，并**生成独立于机器的中间代码（如三地址码、四元式）**；
  - **避坑辨析**：计算表达式的值属于程序**运行期的动态动作**；构造表达式的分析树是**语法分析**阶段的任务；填写符号表始于词法与语法分析阶段。
- **符号表管理**：
  - **声明语句的处理**：主要是将变量名、函数名及其数据类型、作用域、内存分配位置等信息正确登记到**符号表**中；
  - **可执行语句的处理**：在符号表的辅助下，翻译生成**中间代码或目标指令**；
- **错误诊断与处理（高频考点）**：
  - **词法错误**：非法字符、单引号/双引号不配对、数值常量拼写错误；
  - **语法错误**：缺少分号、括号不匹配、`if` 缺少对应的 `then`/`else`、表达式结构不完整（句法结构不符合上下文无关文法产生式）；
  - **静态语义错误（编译时报错）**：**类型不兼容**（例如 C/C++ 中指针与浮点数相加 `"start" + 2.71828`，句法结构符合二元运算，但因指针不允许与浮点数相加而报静态语义错误，绝非语法错误！）、变量未声明先使用、标识符重复定义、形参实参类型/个数不匹配；
  - **动态语义错误（运行时错误）**：程序在逻辑上语法和静态类型均合法，能正常通过编译并生成目标代码，但在**运行期间**引发的逻辑或状态异常错误。典型表现包括：**死循环**（例如 `int k=0; for(;k<100;); {k++;}` 末尾误加分号导致空循环死循环）、除数为 0、数组下标动态越界、空指针异常、堆栈溢出等。

## 7. 中间代码表示体系与后缀表达式操作数栈计算

中间代码是介于源语言和目标机器语言之间的一种内部表达形式。生成中间代码的优势在于：便于进行与机器无关的代码优化，提高编译器的逻辑清晰度与跨平台移植性。

### 常见中间代码表示形式全方位对比

| 中间代码形式 | 结构特点与表示格式 | 优点与适用场景 | 局限性与避坑点 |
|---|---|---|---|
| **后缀式（逆波兰式，RPN）** | 操作符紧随操作数之后，如 `a b +`；表达式中**无需括号**，运算次序完全由运算符出现的先后决定 | 语法结构简单，与**基于操作数栈的虚拟机（如 JVM）**高度契合，便于求值 | 无法显式表达复杂的控制流与多分支跳转 |
| **三元式（Triples）** | 格式为 `(op, arg1, arg2)`；运算结果隐式地通过**该三元式的序号编号（如 (1), (2)）**来引用 | 存储开销小，无冗余变量名 | 进行代码优化（如公共子表达式删除、语句移动）时需大量修改引用序号，极度不便 |
| **四元式（Quadruples）** | 格式为 `(op, arg1, arg2, result)`；显式设立**临时变量名（如 t1, t2）**存放中间计算结果 | **代码优化与机器指令生成首选**；增删或移动指令时无需修改其他指令的操作数字段 | 需要额外的符号表项记录临时变量，空间略增 |
| **抽象语法树（AST）** | 操作符为分支节点，操作数为叶子节点的树状层次结构 | 直观保留程序的层次语法与作用域结构，支持树遍历分析 | 树节点的指针开销较大 |

### 后缀表达式基于操作数栈的通用计算流水线
1. **初始化**：设立一个空的操作数栈（Operand Stack）；
2. **从左至右扫描**：依次遍历后缀表达式中的每一个记号（Token）：
   - 若遇到**操作数（常数或变量值）**：直接压入操作数栈；
   - 若遇到**运算符（如 +, -, *, /）**：
     - 依次从栈顶弹出两个操作数：**第一次弹出的是右操作数 B**，**第二次弹出的是左操作数 A**；
     - 执行运算：`Result = A op B`（注意减法和除法的左右次序绝对不能颠倒！）；
     - 将运算结果 `Result` 重新压入操作数栈；
3. **读取完毕**：扫描结束后，栈中仅剩的唯一下标元素即为整个表达式的最终求值结果。


## 8. 作用域绑定机制与运行时活动记录（栈帧）组织

### 静态作用域（词法作用域）vs 动态作用域

| 对比维度 | 静态作用域（Lexical / Static Scope） | 动态作用域（Dynamic Scope） |
|---|---|---|
| **绑定时间点** | **编译期（静态确定）** | **运行期（动态确定）** |
| **变量引用解析准则** | **根据程序源代码的书写语法嵌套结构**确定。函数内部引用的非局部变量，沿着外层块的词法包含层级向外查找 | **根据程序运行时的函数调用执行栈链**确定。函数内部引用的非局部变量，沿着当前调用它的主调函数链逆向查找 |
| **采用语言** | C、C++、Java、Python、Pascal 等通用编程语言 | 早期的 Lisp 解释器、部分 Bash/Shell 脚本环境变量机制 |
| **可读性与维护性** | 变量归属一目了然，静态类型检查与编译器优化友好 | 变量取值取决于运行时调用路径，极易引发难以排查的副作用 |

### 运行时活动记录（Activation Record / 栈帧）组织结构
当程序调用一个过程或函数时，系统必须在运行时调用栈（Call Stack）上为该次调用分配一块专用的存储空间，称为**活动记录（栈帧）**。典型的栈帧结构自高地址向低地址依次包含：
1. **实参传递区**：主调函数传递给被调函数的参数值或参数地址；
2. **返回地址（Return Address）**：函数执行完毕后，CPU 恢复执行主调函数的下一条指令地址；
3. **动态链（Dynamic Link / 动态指针）**：保存**直接调用本函数的主调函数的栈帧基址指针（FP）**，用于函数返回时恢复主调函数的执行环境；
4. **静态链（Static Link / 存取链）**：在支持过程嵌套的语言中，保存**词法上直接包含本函数的外层过程的最新栈帧基址指针**，专用于跨层级访问外层非局部变量；
5. **保存的寄存器状态**：进入函数前由系统保护的现场通用寄存器内容；
6. **局部变量区**：函数体内部声明的局部变量分配区；
7. **临时变量区**：表达式求值、中间代码计算过程中产生的临时结果存放区。


## 9. 正规表达式代数定律与有限自动机高级变换

### 正规表达式三大运算与核心代数定律
- **选择运算 (`|`)**：`r | s = s | r`（交换律），`r | (s | t) = (r | s) | t`（结合律），`r | r = r`（等幂律）；
- **连接运算**：`r(st) = (rs)t`（结合律），分配律：`r(s | t) = rs | rt`，`(s | t)r = sr | tr`；
- **闭包运算 (`*`)**：
  - `r* = (r|ε)* = r*r* = (r*)*`；
  - **正闭包公式**：`r+ = r r* = r* r`，`r* = r+ | ε`；
  - `r(sr)* = (rs)*r`。

### DFA 状态最小化（分割法）通用三步法
1. **初始状态二分**：将所有状态集合划分为两个互斥的初始子集：**终态集合 F** 与 **非终态集合 (S - F)**；
2. **子集细化分割**：针对当前划分出的每一个状态子集，检查其包含的状态在输入相同字符 `a` 时转换到的目标状态是否落在**同一个子集**中：
   - 若某些状态输入 `a` 后转移到不同子集，则该子集必须分裂为更小的子集；
   - 重复此过程，直到所有子集中的所有状态对任意输入字符的转移行为均完全一致（无法再分割）；
3. **合并代表状态**：在每个最终不可再分的状态子集中选取一个状态作为代表，删除其余等价冗余状态，消除不可达死状态，即得到最简 DFA。


## 10. 第二章核心易错陷阱防坑指南与做题检查清单

### 核心易错陷阱防坑指南
1. **编译期静态语义错误 vs 运行期动态错误**：
   - **陷阱**：遇到“除数为 0”或“死循环”时，误认为是编译期语法错误或语义错误；
   - **避坑法宝**：死循环、数组下标越界、除以零在编译阶段完全符合语法和静态类型约束，编译器能够正常生成目标代码，**只能在运行期被发现，属于运行期动态错误**；类型不兼容（如浮点数与指针相加）才是编译期静态语义错误。
2. **形参修改回写实参的判定边界**：
   - **陷阱**：只要看到函数内部对形参重新赋值，就误以为实参一定被修改；
   - **避坑法宝**：传值调用下形参是实参的独立副本，函数内任何修改绝不影响实参；**只有传引用调用（或通过指针解引用操作指向的内存空间）时，对形参内容的修改才会回写改变实参**。
3. **短路求值中被跳过的副作用计算**：
   - **陷阱**：在计算 `a || (b = b + 1)` 时，若 `a` 为真，误以为后面的自增赋值仍会执行；
   - **避坑法宝**：逻辑或 `||` 前项为真时立即触发短路，后项子表达式**根本不会被求值执行**，因此其中的赋值、函数调用等任何副作用均不会发生。
4. **有限自动机终态数量误区**：
   - **陷阱**：误以为“具有多个终态”是 NFA 的特有属性；
   - **避坑法宝**：DFA 和 NFA **都可以拥有多个终态**！NFA 的非确定性严格体现在**存在 ε 转换**或**同一输入字符对应多个后继转移状态**。

### 第二章做题自检检查清单
- [ ] 传参题目先标出形参是传值还是传引用，牢记局部变量不改写传值实参；
- [ ] 中缀转后缀快速验证：后缀表达式中操作数的相对先后顺序与中缀完全相同，仅运算符后移；
- [ ] 后缀式栈计算：弹出两个操作数时，注意**先弹出的是右操作数，后弹出的是左操作数**；
- [ ] 短路逻辑计算：与运算遇假全假且停止，或运算遇真全真且停止；
- [ ] 编译四阶段顺口溜：“预编译（展开宏和头文件）→ 编译（生成汇编）→ 汇编（生成机器目标码）→ 链接（合并库生成可执行程序）”。
