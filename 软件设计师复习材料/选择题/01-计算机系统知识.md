# 第一章 计算机系统知识

## 1. 校验码体系：奇偶校验、CRC 与海明码

### 核心校验机制对比

| 校验码 | 编码原理 | 检错能力 | 纠错能力 | 核心公式与特点 |
|---|---|---|---|---|
| **奇偶校验码** | 增加 1 位校验位，使码字中“1”的个数为奇数或偶数 | 仅能检测**奇数位**错，偶数位错漏检 | **无纠错能力** | 只能发现错误，无法定位错误位置 |
| **海明码 (Hamming)** | 利用多组奇偶校验位分布在 2^i 位置，形成多维校验交叉定位 | 可检测双位错（加总校验位时） | **可纠正 1 位错** | **校验位不等式**：2^k ≥ n + k + 1<br>（n 为数据位，k 为校验位） |
| **循环冗余校验 (CRC)** | 利用生成多项式进行模 2 除法运算产生余数作为校验位 | 检错能力极强（突发错误） | 软考中主要用于检错 | **左移 r 位补零，模 2 除法求余数**<br>发送码字结构：**k 位数据位在前，r 位校验位在后** |

### 编码距离与检纠错定理
- **码距（Code Distance）**：一个编码系统中任意两个合法码字之间不同二进制位数的最小值。
  - 若码距 d ≥ e + 1，则能**检测出 e 个错误**；
  - 若码距 d ≥ 2e + 1，则能**纠正 e 个错误**；
  - 若码距 d ≥ 2e + t + 1（t > e），则能**纠正 e 个错误并同时检测出 t 个错误**。

### CRC 编码解题通用步骤
1. 确定校验位数：若生成多项式 G(X) 的最高次数（阶数）为 r，则校验位长度为 r 位，对应二进制除数有 r+1 位；
2. 数据后补零：原始数据位 k 位，末尾补 r 个 0，构成 k+r 位被除数；
3. 模 2 除法：被除数与多项式二进制系数序列进行模 2 除法（加减法等价于异或运算，不产生进位/借位）；
4. 拼接码字：求得的 r 位余数替换掉末尾补的 r 个 0，最终码字为“k 位数据位 + r 位余数校验位”（总长 k+r 位）。
5. **易错陷阱**：CRC 校验位严格紧随在数据位末尾，不是前置，也不是等间隔插入；模 2 除法商的每一位取决于当前被除首位是否为 1（为 1 商 1，为 0 商 0）。

## 2. 浮点数表示与运算：表示范围、规格化与加减四步法

### 浮点数表示格式与范围
浮点数通常表示为：N = (-1)^S × M × 2^E
- **阶码 E**：常用移码或补码表示定点整数，**决定数值的表示范围**；
- **尾数 M**：常用原码或补码表示定点小数，**决定数值的精度**；
- **数符 S**：决定正负。

#### 尾数规格化判断准则
- **原码规格化**：最高数值位必须为 1，即正数为 0.1xxxx…，负数为 1.1xxxx…；尾数绝对值范围为 [0.5, 1 - 2^(-(n-1))]；
- **补码规格化**：**符号位与最高数值位必须互异（不同）**！
  - 正数补码：0.1xxxx…（范围 [0.5, 1 - 2^(-(n-1))]）；
  - 负数补码：1.0xxxx…（范围 [-1, -0.5 - 2^(-(n-1))]）。

#### 最值极值求解模型
- **最大正数**：阶码取最大正数，尾数取最大正数；
- **最小负数**：阶码取最大正数，尾数取最小负数（补码为 -1）；
- 若阶码为 R 位移码（含符号位），最大阶码通常为 2^(R-1) - 1；若尾数为 M 位补码（含符号位），最大正数尾数为 1 - 2^(-(M-1))。两部分分别确定后再计算总值。

### 浮点数加减运算四步法
1. **零操作数检查**：若有一方或双方为零，直接得出结果；
2. **对阶操作（小阶向大阶看齐）**：
   - 求阶差 Δ E = E_1 - E_2；
   - 将小阶数的尾数**右移** Δ E 位，其阶码增加 Δ E（使两数阶码相等）；
   - 右移时低位可能移出丢失，需注意舍入。
3. **尾数加（减）运算**：完成实际的尾数数值运算；
4. **结果规格化及溢出判断**：
   - **右规**：尾数运算结果溢出（如双符号位出现 01 或 10）时，尾数右移 1 位，**阶码加 1**；若阶码超过最大值，则产生**阶码上溢**（中断报错）；
   - **左规**：尾数最高有效位不是有效数值（如双符号位出现 00.0… 或 11.1…）时，尾数连续左移，每左移 1 位**阶码减 1**；若阶码低于最小值，产生**阶码下溢**（通常按机器 0 处理）。
   - **核心口诀**：**右规右移尾数、阶码加一；左规左移尾数、阶码减一。运算流程：查零 → 对阶 → 尾数加减 → 规格化与舍入。**

## 3. 中断来源：程序异常属于软件中断

中断按来源可先区分为：

- **软件中断/异常**：由正在执行的指令或程序异常触发，例如除零、非法指令、越界等；
- **外部硬件中断**：由外设或时钟等外部事件触发，例如键盘输入、定时器溢出；
- **硬件故障**：如电源故障，属于更底层的硬件异常，不应误归为由程序逻辑触发的软件中断。

做题时先问“这个事件是否由当前指令执行产生”。是则优先选软件中断/异常；外设请求和时钟事件则选硬件中断。

## 4. 补码：为运算而设计，不以直观对应见长

补码的关键性质：

- 零的表示唯一；
- 减法可转换为加法；
- 符号位可与数值位一起参与加法运算；
- 负数的补码需经过转换才能得到真值，因此它与真值的对应关系**不直观**。

对于 n 位补码，表示范围通常为 `-2^(n-1)` 到 `2^(n-1)-1`。最小负数没有相反数可在同一 n 位补码范围内表示，这是判断溢出题的重要边界。

- 不论表示定点整数还是定点小数，n 位补码都有 `2^n` 个不同码字；
- 8 位补码整数范围为 `[-128, 127]`；
- 双符号位表示中，`00` 为正、`11` 为负；相加结果出现 `01` 或 `10` 即两符号位不同，二者异或为 1，表示溢出。

### 逻辑代数与布尔运算等价化简
- **核心逻辑运算定义**：
  - **逻辑与（AND / ·）**：全 1 为 1，有 0 为 0；
  - **逻辑或（OR / +）**：有 1 为 1，全 0 为 0；
  - **逻辑非（NOT / ¬）**：非 0 为 1，非 1 为 0；
  - **逻辑异或（XOR / ⊕）**：相异为 1，相同为 0，表达式为 `A ⊕ B = ¬A · B + A · ¬B`；
  - **逻辑同或（XNOR / ⊙）**：相同为 1，相异为 0，表达式为 `A ⊙ B = A · B + ¬A · ¬B`。
- **做题高频恒等式与等价变换**：
  - **异或取反关系**：`¬(A ⊕ B) = A ⊙ B = A · B + ¬A · ¬B`；对单一操作数取反等价于整体取反：`¬A ⊕ B = A ⊕ ¬B = ¬(A ⊕ B) = A · B + ¬A · ¬B`；
  - **德·摩根定律（反演律）**：`¬(A + B) = ¬A · ¬B`，`¬(A · B) = ¬A + ¬B`；
  - **吸收律与分配律**：`A + A · B = A`，`A · (A + B) = A`，`A + ¬A · B = A + B`，`A · (B + C) = A · B + A · C`。

## 5. 冯·诺依曼计算机：程序和数据同存于存储器

核心特征包括：

- 由运算器、控制器、存储器、输入设备、输出设备组成；
- 指令和数据均用二进制表示；
- 指令和数据以同等地位存放在**存储器**中，可按地址访问；
- 指令通常按存储顺序自动取出并执行，程序执行过程由指令控制；
- CPU 执行指令来实现程序功能。

Cache 是主存内容的高速副本，并非“程序固定在主存、数据固定在 Cache”的分工。遇到这种绝对化表述应警惕。

## 6. CPU 寄存器与内部核心部件：按“存什么”与“功能划分”区分

### CPU 两大核心功能部件划分
- **运算器（ALU、AC、PSW、DR、通用寄存器）**：
  - 承担执行各种算术运算（加减乘除）和逻辑运算（与或非异或）的工作；
  - 主要由**算术逻辑单元（ALU）**、**累加器（AC / Accumulator）**、**状态条件寄存器（PSW）**、**通用寄存器组**和**数据缓冲寄存器（DR）**等组成。
- **控制器（PC、IR、ID、时序电路、AR）**：
  - 控制整个 CPU 的工作，包括指令控制、时序控制和总线控制；
  - 主要由**程序计数器（PC）**、**指令寄存器（IR）**、**指令译码器（ID）**、**地址寄存器（AR）**和**时序发生器**等组成。

### 核心寄存器分类对照表

| 寄存器名称 | 缩写 | 所属功能部件 | 核心职能与避坑关键点 |
|---|---|:---:|---|
| **程序计数器** | **PC** | 控制器 | **存放 CPU 即将执行的下一条指令的主存地址**；顺序执行时自动递增，遇到转移指令时被置入目标跳转地址 |
| **指令寄存器** | **IR** | 控制器 | **暂存当前正在执行的指令代码**；操作码送至指令译码器（ID）分析，操作数地址送至地址引脚或寻址部件 |
| **指令译码器** | **ID** | 控制器 | 对 IR 中的操作码进行解析与译码，产生相应的微操作控制信号序列 |
| **存储器地址寄存器** | **AR / MAR** | 控制器/接口 | **暂存 CPU 访问主存或外设的内存物理地址**，连接地址总线 |
| **累加寄存器** | **AC** | 运算器 | **为算术逻辑单元（ALU）暂存运算操作数及中间运算结果**，属于通用型数据寄存器 |
| **数据缓冲寄存器** | **DR / MDR** | 运算器/接口 | **暂存由主存读出或写入主存的数据字**，作为 CPU 与主存、总线之间的数据缓冲中转站 |
| **程序状态字寄存器** | **PSW** | 运算器 | **保存算术逻辑运算后的条件状态标志**（如进位/借位标志 C、溢出标志 V、零标志 Z、符号标志 S）以及系统运行工作状态（如目态/管态、允许/屏蔽中断标志） |

> **极速做题口诀**：
> 运算器负责“算”，核心是 ALU、累加器 AC、状态寄存器 PSW 和通用寄存器；
> 控制器负责“控”，核心是 PC（下一条地址）、IR（当前指令）、时序电路和译码器 ID。
> 题干出现“运算器主要由算术逻辑单元、状态寄存器、通用寄存器和（ ）组成”，必选**累加器**；程序计数器与指令寄存器属于控制器！

## 7. 奇偶校验：可检奇数位错，不能纠错

一位奇校验要求码字中“1”的总数为奇数。发生奇数个比特翻转时，奇偶性改变，能发现错误；发生偶数个比特翻转时，奇偶性不变，可能漏检。

一位奇偶校验只能检错，不能指出错误位置，因而不能纠错。题目中“所有奇数位/偶数位出错”描述的是位置编号而非错误位数量，不能据此判断检测能力。

## 8. DMA 与中断：并行传输，但地址是主存物理地址

- 程序查询方式下，CPU 主动轮询外设，CPU 与外设不能充分并行；
- 中断方式下，外设主动请求 CPU，CPU 处理中断时需要保护、恢复现场；
- DMA 由 DMA 控制器在外设与**主存**之间直接成块传输，CPU 仅在开始时设置主存物理地址、磁盘地址和数据量，完成一个块后再中断 CPU。

因此，能让 CPU 与外设并行工作的控制方式是中断和 DMA；DMA/中断控制器所用的数据地址是主存物理地址，而非 Cache、虚拟地址或磁盘扇区地址。

## 9. 存储层次：寄存器最快，硬盘属于辅存

存储层次从靠近 CPU 到远离 CPU 可记为：**寄存器 → Cache → 主存（DRAM）→ 辅存（硬盘等）**，越靠近 CPU 访问越快。

- DRAM 用电容存储信息，需周期性刷新；SRAM 不需刷新；
- 硬盘、光盘均为辅存；
- Flash 是非易失存储器，以块擦除，适合替代 ROM/EPROM 存放代码或 Bootloader，不能作为主存来替代 RAM；
- DMA 单次传送一个数据占用一个总线周期。

## 10. 总线：三总线的组成与 PCI/SCSI 分类

### 系统三总线架构
按功能，计算机系统总线由三大总线组成：
- **数据总线（DB）**：双向传输，用于在 CPU、主存和外设之间传递数据字，其宽度决定了一次传输的二进制位数；
- **地址总线（AB）**：单向传输，由 CPU 发出指向主存或 I/O 端口的地址，其宽度直接决定了 CPU 的**直接寻址物理空间上限**（若地址线为 32 位，则最大直接寻址空间为 `2^32 B = 4 GB`）；
- **控制总线（CB）**：混合双向传输，用于发出读写控制命令、时序脉冲、中断请求以及握手确认信号。

### 内总线 vs 外总线分类
- **并行内总线**：PCI（Peripheral Component Interconnect）、ISA 等，连接计算机内部各扩展插卡；
- **并行外总线 / 串行外总线**：传统 SCSI、IDE 是并行外总线；USB、SATA、PCIe 是高速串行总线。
- **连接对象规范**：系统总线用于连接接口和外设；CPU 内部的运算器、控制器和内部寄存器之间使用的是**内部专用连接结构**，不属于外部系统总线。

### 总线通信控制方式：同步传输 vs 异步传输
- **同步传输（Synchronous Transmission）**：通信双方由**统一的集中时钟脉冲信号**控制，以固定的时钟周期发送和接收数据（通常以数据块为单位高速连续传输），通信双方必须保持严格的时钟同步。典型应用：CPU 与内存储器、Cache、内部高速总线之间的高速信息交换；
- **异步传输（Asynchronous Transmission）**：通信双方**没有统一的时钟基准**，各部件拥有各自独立的时钟。数据通常以单个字符或字节为单位离散传输，收发双方依靠握手应答联络信号（如“请求/应答”）协调传输节奏。典型应用：CPU/I/O 接口与打印机、键盘、低速外部设备之间的数据交换。

## 11. RISC 与 CISC：精简、寄存器多、硬布线

| 特征 | RISC | CISC |
|---|---|---|
| 指令集 | 简单、格式较少且常固定长度 | 复杂、功能较强 |
| 寄存器 | 通用寄存器较多 | 通常较少 |
| 控制器 | 组合逻辑/硬布线 | 微程序控制 |
| 流水线 | 更适合 | 相对不利 |
| 工艺 | 更符合 VLSI 的规整性 | 实现较复杂 |

RISC 的编译器通常要以较大的子程序库弥补简单指令；选择题若问“不正确”，常见陷阱是把 RISC 说成比 CISC 指令系统更复杂。

### 指令级并行体系：超标量、超流水线与超长指令字（VLIW）
- **超标量（Superscalar）**：CPU 内置多条流水线与多个功能执行部件，在同一个时钟周期内**并发发射执行多条独立指令**（依靠硬件进行指令动态调度与并发控制）；
- **超流水线（Superpipelining）**：将传统流水线各阶段进一步细分为更多更浅的流水段，成倍提高主频（在更高时钟频率下每时钟周期仍发射一条指令）；
- **超长指令字（VLIW，Very Long Instruction Word）**：**由编译程序在编译时静态分析指令间的并行性**，将多条相互独立、可并行执行的微操作指令组合封装为一个固定的超长指令字（例如 128 位或 256 位），由硬件多个执行部件同时并行执行。其核心优势是极大简化了 CPU 硬件控制逻辑，但对编译器代码优化提出了极高要求。

## 12. 取指与中断：由时序阶段区分，响应止于进入服务程序

同一主存中的二进制序列是否作为指令或数据读取，取决于**指令周期所处阶段**：取指阶段读取指令，分析、执行阶段按需要读取操作数，不能依据存储单元位置或地址方式区分。

中断响应时间是从中断请求发出到 CPU 开始进入中断服务程序的时间；不包括完整的服务处理过程。

## 13. 系统核心计算模型：存储编址、指令流水线与磁盘存取

### 存储器编址与芯片容量扩展
1. **地址空间容量计算**：
   - 地址单元数 = 末地址 - 首地址 + 1；
   - 16 进制减法遇不够借 1 当 16。例如：从 `A1000H` 到 `B13FFH`：
     B13FFH - A1000H + 1 = 103FFH + 1 = 10400H = 1 × 16^4 + 4 × 16^2 = 65536 + 1024 = 66560  个单元（即 65KB）
   - **按字节编址**：每个单元为 8 bit（1B），总容量 = 单元数 × 1B；
   - **按字编址**：每个单元为一个机器字长（如 16 bit 或 32 bit），总容量 = 单元数 × 字长。
2. **所需芯片数量公式**：
   所需芯片总数 = 总存储容量 / 单片存储芯片容量 = (总字数 × 总位数) / (单片字数 × 单片位数)
   - **位扩展**：芯片字数满足但位数不够（增加数据线）；
   - **字扩展**：芯片位数满足但字数不够（增加地址线，经译码器片选）。
   - **典型例题推导**：
     > **题目**：某系统内存按字节编址，地址空间为 `90000H` 到 `CFFFFH`，若用 16K × 8位 的存储芯片构造，至少需要（ ）片。
     >
     > **解题步骤**：
     > 1. 计算地址单元数（字节数）：CFFFFH - 90000H + 1 = 40000H；
     > 2. 转换为十进制/K：40000H = 4 × 16^4B = 4 × 65536B = 262144B = 256KB；
     > 3. 单芯片容量：16K × 8位 = 16KB；
     > 4. 所需芯片片数：256KB / 16KB = 16 片。因此至少需要 16 片。

### 指令流水线性能全指标计算
设一条指令分为 k 个流水段，各段耗时分别为 t_1, t_2, ..., t_k，流水线周期 Δt = max(t_1, t_2, ..., t_k)。
1. **执行时间 T**：
   - **理论公式**（优先采用）：T = (t_1 + t_2 + ... + t_k) + (n - 1) × Δt（首条指令各段之和，后续每条耗时一个周期）；
   - **实际/工程公式**（各段耗时均补齐到 Δt）：T = k × Δt + (n - 1) × Δt = (k + n - 1) × Δt。
2. **吞吐率（Throughput，TP）**：
   TP = n / T （最大吞吐率 TP_max = lim(n→∞) n / T = 1 / Δt）
3. **加速比（Speedup，S）**：
   S = T_不使用流水线（串行执行耗时） / T_使用流水线（流水线执行耗时） = (n × Σ(i=1..k) t_i) / T
4. **流水线效率（Efficiency，E）**：
   E = (n 个任务占用的有效时空区) / (k 个流水段总时空区) = T_0 / (k · T) = S / k

### 磁盘存取时间与存储容量模型
1. **读取一个物理块的总时间构成**：
   T_存取 = T_寻道时间 + T_旋转延迟时间 + T_传输时间
   - **寻道时间**：磁头移动到目标磁道所需时间（由跨道数 × 每道时间决定）；
   - **旋转延迟时间**：盘片旋转使目标扇区转到磁头下方的时间（平均按盘片旋转半周计算）；
   - **传输时间**：读取扇区数据并送出所需的时间；
   - **非连续/连续读取**：非连续离散存储时，每一块数据都需要经历一次独立的“寻道 + 旋转延迟 + 传输”全过程。
2. **磁盘存储容量计算模型**：
   - **磁道数计算**：磁道数 = 记录面有效宽度 × 磁道密度 = [(外直径 - 内直径) / 2] × 磁道密度；
   - **格式化容量**：记录面数 × 每面磁道数 × 每磁道扇区数 × 每扇区字节数；
   - **非格式化容量**：记录面数 × 每面磁道数 × 内圈磁道周长 × 最大位密度。

### Cache 存储器地址映射与性能模型
1. **Cache 三大地址映射机制**：
   - **直接映射**：主存的每一块只能映射到 Cache 中固定的某一行（行号 = 主存块号 mod Cache总行数）。硬件实现极其简单、访问速度最快，但块冲突率最高、空间利用率低；
   - **全相联映射**：主存的任意一块可以映射到 Cache 中的任意一行。空间利用率最高、冲突率最低，但需要庞大的相联比较器，硬件成本高且地址变换慢；
   - **组相联映射**：前两者的折中。将 Cache 分成若干组，主存块映射到固定组，而在组内可以映射到任意一行（组间直接映射，组内全相联映射，如 2 路、4 路组相联）。
   - **核心属性**：Cache 与主存之间的地址变换与内容替换**完全由硬件自动完成**，对系统程序员和应用程序员都是透明的。
2. **Cache 性能指标计算模型**：
   - 设 Cache 命中率为 h（0 ≤ h ≤ 1），Cache 存取时间为 t_c，主存存取时间为 t_m（t_m > t_c）：
     - **系统平均访问时间**：t_avg = h × t_c + (1 - h) × t_m
     - **Cache 访问效率**：e = t_c / t_avg = t_c / [h × t_c + (1 - h) × t_m]

## 14. 安全通信体系：证书认证、数字签名与加密算法

### 核心加密与鉴别机制
- **对称密钥加密（共享密钥）**：加密解密使用相同密钥。速度快、适合大量数据加密。典型算法：**DES、3DES、AES、RC4、IDEA**；
- **非对称密钥加密（公钥密码）**：公钥加密则私钥解密，私钥加密则公钥解密。速度慢，常用于密钥分发与数字签名。典型算法：**RSA、ECC、DSA**、国密 **SM2**；
- **信息摘要 / 散列算法**：单向不可逆、抗碰撞。用于验证数据完整性。典型算法：**MD5（128位）、SHA-1（160位）、SHA-256（256位）**。

### 数字签名与数字证书的区别与联动
- **数字签名（防伪造、不可否认）**：
  - **流程**：发送方用自己的**私钥**对消息摘要进行加密生成签名；接收方用发送方的**公钥**验证签名；
  - **核心价值**：确认发送方身份的真实性与消息传输的不可否认性。
- **数字证书（防冒名公钥）**：
  - **权威背书**：由 CA 认证中心签发，内含证书持有者公钥及其身份信息，并由 **CA 用自己的私钥签名**；
  - **验证方式**：用户使用 **CA 的公开公钥**验证 CA 的签名，从而确信该网站或个人公钥的真实性与合法性；
  - 工业标准：X.509 证书规范（常用 RSA / ECC 算法）。
- **安全应用协议**：
  - 邮件安全：PGP、S/MIME（MIME 本身仅为多用途互联网邮件扩充协议，不提供加密安全服务）；
  - 传输安全：SSL/TLS、HTTPS（TCP 443 端口）、IPsec（网络层安全）。

## 15. 可靠性、可用性与可维护性（RAM）与系统可靠度计算

### 核心度量指标
1. **可靠性（Reliability，R）**：
   - 描述系统在规定条件下和规定时间内正常工作的概率；
   - 通常与 **MTTF（平均无故障时间）** 对应；失效率 λ = 1 / MTTF，可靠度函数 R(t) = e^(-λ t)。
2. **可维护性（Maintainability，M）**：
   - 描述系统发生故障后在规定时间内完成修复的概率；
   - 与 **MTTR（平均故障修复时间）** 对应；修复率 μ = 1 / MTTR，可维护度 M = 1 / (1 + MTTR) 或 M(t) = 1 - e^(-μ t)。
3. **可用性（Availability，A）**：
   - 描述在给定时刻系统能够正确运行的概率（正常工作时间占总运行时间的比例）；
   - **通用计算公式**：
     A = MTBF / (MTBF + MTTR) ≈ MTTF / (MTTF + MTTR)
   - 其中 MTBF 为平均故障间隔时间（MTBF = MTTF + MTTR）；在 MTTR 远小于 MTTF 的系统中有 MTBF ≈ MTTF。

### 串并联系统可靠度计算法则
- **串联系统**：所有部件均正常系统才正常；任一部件失效系统即失效。
  R_串 = R_1 × R_2 × ... × R_n
  （部件越多，系统可靠度越低）。
- **并联系统**：只要有一个部件正常系统就能正常；所有部件全部失效系统才失效。
  R_并 = 1 - (1 - R_1)(1 - R_2) ... (1 - R_n)
  （若两个相同部件并联，可靠度为 1 - (1 - R)^2）。
- **混联系统（模冗余/串并混合）**：按系统拓扑结构自内向外化简计算，先将局部并联块化简为一个等效模块，再参与整体串联乘积。
  - 例：两部件并联后再与两端部件串联：R = R_前 × [1 - (1 - R_并)^2] × R_后。

## 16. 多媒体技术基础：音频采样、图像分辨率与数据量计算

### 音频采样与奈奎斯特（Nyquist）采样定理
- **采样频率**：在时间轴上对连续模拟音频信号进行离散化采样的速率（单位为 Hz）。
- **奈奎斯特（Nyquist）采样定理**：为了不失真地恢复模拟信号，采样频率 f_s 必须大于或等于输入信号最高有效频率 f_max 的 2 倍，即 f_s ≥ 2 × f_max。
  - **人耳听觉范围**：20 Hz ～ 20 kHz；
  - **电话语音信号**：最高频率一般为 3.4 kHz（约 4 kHz），因此数字电话语音的标准采样频率定义为 **8 kHz**（8000 Hz ≥ 2 × 4000 Hz）；
  - **CD 音质**：采样频率为 **44.1 kHz**。
- **声卡/MIC 输入**：计算机通过 MIC（话筒接口）接收到的原始声音信号是**模拟信号**，需经声卡中的 A/D（模数转换器）转换为数字信号后存入计算机。

### 图像与视频数据量计算模型
- **DPI（Dots Per Inch）**：扫描分辨率/打印分辨率，表示每英寸长度上的像素点数（Dots）。
  - 例如以 150 DPI 扫描 3 × 4 英寸的照片：
    - 水平像素点数 = 3 英寸 × 150 DPI = 450 像素；
    - 垂直像素点数 = 4 英寸 × 150 DPI = 600 像素；
    - 图像总像素数 = 450 × 600 = 270,000 像素。
- **颜色深度（位深）与未压缩数据量**：
  - **真彩色（24 位）**：每个像素占 24 位（即 3 字节，RGB 各 8 位）；
  - **未压缩图像数据量（Byte）** = 水平像素 × 垂直像素 × (颜色深度（bit） ÷ 8)；
  - 例如上述 450 × 600 像素的 24 位真彩色图像，数据量 = 450 × 600 × (24 ÷ 8) = 270,000 × 3 = 810,000 Byte。

## 17. Flynn 计算机体系结构分类体系

根据计算机在同一时间内所能处理的**指令流（Instruction Stream）**与**数据流（Data Stream）**的多寡，Michael J. Flynn 于 1966 年提出了经典的四分法：

| 体系结构类别 | 英文全称 | 指令流数量 | 数据流数量 | 处理器与内存架构特征 | 典型系统实例与做题线索 |
|---|---|:---:|:---:|---|---|
| **单指令流单数据流 (SISD)** | Single Instruction Single Data | 单单一流 | 单单一流 | 传统的单微处理器架构，硬件由单个控制部件、单个算术逻辑单元和单个主存构成 | 传统单核冯·诺依曼计算机、早期单片机、单核 PC |
| **单指令流多数据流 (SIMD)** | Single Instruction Multiple Data | 单单一流 | 多重多流 | 一个控制部件控制多个执行单元（PE），各个执行单元在同一时钟周期内接收同一指令，但操作各自不同的数据分量 | **阵列处理机、向量处理机、GPU（图形处理器）、多媒体 SIMD 指令扩展（AVX / SSE）** |
| **多指令流单数据流 (MISD)** | Multiple Instruction Single Data | 多重多流 | 单单一流 | 多个控制部件处理不同的指令序列，但作用于同一数据流上 | **理论模型，实际计算机体系中极罕见**（部分高容错冗余系统或心动阵列计算机有近似实现） |
| **多指令流多数据流 (MIMD)** | Multiple Instruction Multiple Data | 多重多流 | 多重多流 | 包含多个独立的处理器，每个处理器自主读取各自的指令序列并处理各自的数据集合 | **现代多核多处理器、对称多处理系统 (SMP)、大规模并行处理系统 (MPP)、分布式计算机集群 (Cluster)** |

> **极速做题口诀**：
> “阵列向量选 SIMD，多核集群选 MIMD；传统单核是 SISD，空间罕见是 MISD。”


## 18. 指令系统与指令七大寻址方式

指令通常由**操作码（Opcode）**与**地址码（Operand/Address Code）**两部分构成。寻址方式是指寻找操作数有效地址（Effective Address，EA）或下一条指令地址的方法。

### 指令寻址与数据寻址核心对比

| 寻址方式类别 | 英文名称 | 有效地址 EA 计算模型 | 访存次数 | 核心特征与适用场景 |
|---|---|---|:---:|---|
| **立即寻址** | Immediate Addressing | **无 EA**（操作数直接存放在指令地址码字段中） | **0 次** | **执行速度最快**；常用于为寄存器赋初值或提供固定常数（如 `MOV AX, 100`） |
| **寄存器寻址** | Register Addressing | **EA = R_i**（操作数存放在 CPU 内部寄存器中） | **0 次** | **速度极快仅次于立即寻址**；无需访问内存总线（如 `MOV AX, BX`） |
| **直接寻址** | Direct Addressing | **EA = A**（指令中给出的地址码直接就是主存物理地址） | **1 次** | 地址码固定，无法动态修改；不利于程序浮动和模块化重定位 |
| **寄存器间接寻址** | Register Indirect Addressing | **EA = (R_i)**（寄存器中存放的是操作数在主存中的物理地址） | **1 次** | 比直接寻址更具灵活性，支持通过寄存器指针遍历线性结构 |
| **间接寻址** | Indirect Addressing | **EA = (A)**（指令地址码指向主存单元，该单元存放操作数的有效地址） | **≥ 2 次** | **执行速度最慢**；支持多级嵌套间接寻址，便于实现指针链表访问，但访存开销大 |
| **相对寻址** | Relative Addressing | **EA = (PC) + A**（以当前程序计数器 PC 的值为基准加上偏移量 A） | **1 次** | **常用于编写位置无关代码（PIC）与相对条件跳转指令**；操作数随程序在内存中浮动 |
| **变址寻址** | Indexed Addressing | **EA = (R_x) + A**（变址寄存器 R_x 内容加上指令偏移量 A） | **1 次** | **由程序员在程序中指定和修改变址寄存器**；特别适用于**数组遍历、向量处理和循环结构** |
| **基址寻址** | Base Addressing | **EA = (R_b) + A**（基址寄存器 R_b 内容加上指令位移量 A） | **1 次** | **由操作系统内核管理和设定基址**，程序员不可随意修改；专用于**多道程序动态重定位与大容量物理寻址** |

### 核心寻址速度排序与做题判定法则
1. **执行速度由快到慢排序**：
   `立即寻址（0次访存） > 寄存器寻址（0次访存，仅访问内部寄存器） > 直接寻址 / 寄存器间接寻址（1次访存） > 间接寻址（至少2次访存，最慢）`；
2. **变址寻址 vs 基址寻址核心判定口诀**：
   - **变址寻址**：面向**用户程序与数组下标**，变址寄存器由程序员自由修改，基准地址 A 固定；
   - **基址寻址**：面向**系统管理与程序浮动**，基址寄存器由操作系统统一控制，位移量 A 固定。


## 19. 第一章核心易错陷阱防坑指南与做题检查清单

### 核心易错陷阱防坑指南
1. **流水线周期 Δt 计算误区**：
   - **陷阱**：遇到指令各段耗时不同的流水线题目时，误将各段耗时相加求平均值作为流水线周期；
   - **避坑法宝**：流水线周期严格取各流水段执行时间中的**最大值**（即瓶颈段耗时）：`Δt = max(t₁, t₂, ..., t_k)`。
2. **Cache 写操作策略混淆**：
   - **陷阱**：混淆写直达（Write-through）与写回（Write-back）对主存的写入时机；
   - **避坑法宝**：**写直达（全写）**是只要写 Cache 就必须**同时写主存**，主存随时保持最新状态；**写回（写不全）**是只写 Cache 并标记脏位，**只有该块被替换淘汰时才写回主存**。
3. **系统可靠度与失效率关系颠倒**：
   - **陷阱**：可靠性计算时，误将失效率 λ 直接相乘来当成串联系统的可靠度；
   - **避坑法宝**：在恒定失效率模型下，串联系统的失效率是**累加**的（`λ_sys = ∑λ_i`），而串联系统的可靠度才是**相乘**的（`R_sys = ∏R_i`）。
4. **PC 与 IR 职责混淆**：
   - **陷阱**：将“暂存当前执行指令”的职责错选给程序计数器 PC；
   - **避坑法宝**：PC（程序计数器）始终存放**下一条指令的主存地址**；IR（指令寄存器）存放**当前正在执行的指令机器码**。
5. **寻址方式灵活性与访存开销对立**：
   - **陷阱**：误以为间接寻址速度快、直接寻址可以程序浮动；
   - **避坑法宝**：直接寻址地址写死在指令中不可浮动；间接寻址至少访存两次最慢；相对寻址与基址寻址才能良好支持程序重定位。

### 第一章做题自检检查清单
