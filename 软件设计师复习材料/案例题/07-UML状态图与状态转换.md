# UML 状态图与状态转换案例

> 本专题专为软考下午试题三（UML 面向对象分析与设计之“状态机图与生命周期建模”，15 分必答题）定制。考生拿到状态机题目后，可直接对照小问设问类型，定位到对应作答卡快速解题。

---

## 1. 状态图题型识别与通用破题流程

### 1.1 试题识别与题面结构
- **试题位置**：下午试题三（必答题，满分 15 分，考查对象动态生命周期）。
- **题面两件套**：
  1. **实体生命周期状态描述**：详细阐述单个对象在其生命周期内经历的各个阶段（如自动售货机投币出货、电商订单备货发货、航空会员积分升级）；
  2. **状态机图（半成品）**：
     - 初态（实心黑圆 `●`）与终态（同心实心圆 `◉`）；
     - 圆角矩形（状态 `S1～Sn`，内含状态名）；
     - 迁移箭线（标注格式：`事件 [守卫条件] / 动作`）。

### 1.2 考场四步快速解题流水线
```text
第 1 步：圈持续性词，定状态名 → 圈出形容词或名词短语（如“待付款”、“空闲”、“备货中”），填入圆角矩形
  ↓
第 2 步：抓瞬时动词，定触发事件 → 寻找引起状态跃迁的外来输入或时钟信号（如“投币”、“点击支付”）
  ↓
第 3 步：提取条件动作，规范语法 → 方括号包守卫条件 [Guard]，斜杠后紧跟原子动作 /Action
  ↓
第 4 步：排查死胡同，验证闭环自洽 → 检查各分支是否有退回路径（如投币不足退款、支付失败取消）
```

## 2. 状态图核心作答卡

---

### 作答卡 UML-ST-01：状态机要素与状态识别

- **【题型识别】**：常见设问：“使用说明中的词语，给出图中的状态 S1～Sn 的名称。”（通常 4～8 分）。
- **【目标产出】**：状态编号对应的名称列表（如 `S1: 空闲 (Idle); S2: 待付款; S3: 备货中; S4: 已发货`）。
- **【题干取证】**：
  - 寻找描述对象处于**某一持续性时间段、等待某事发生或持续执行某活动**的语句；
  - 核心词性：**名词短语或形容词短语**（如“挂起”、“就绪”、“已出票”、“银卡会员”）。
- **【推理步骤】**：
  1. 观察初态 `●` 后的第一个状态：通常是“初始化”、“就绪”或“空闲 (Idle)”；
  2. 观察终态 `◉` 前的最后一个状态：通常是“已完成”、“已取消”或“已销毁”；
  3. 观察中间状态的迁移路径：
     - 若支付成功后仍需备货且发货前离开该状态，可候选为“备货中”；最终名称按题设状态职责确定；
  4. 绝不将瞬时动作（如“用户投币”）填为状态名。
- **【答案形态】**：规范英文或中文状态名（如 `Preparing`, `待出票`）。
- **【知识依赖】**：[状态与事件严格辨析](#51-状态机图的核心要素与辨析规范)。
- **【易错与自检】**：
  - *陷阱*：将动词事件（如“支付费用”、“按下按钮”）误填为状态名；
  - *自检*：这个词能不能用“该对象正处于……状态”造句？能造通才是合法状态名！

### 作答卡 UML-ST-02：反应型与事务型状态流转

- **【题型识别】**：常见设问：“补充图中迁移箭线上的事件、守卫条件与动作 (1)～(n)。”（通常 3～6 分）。
- **【目标产出】**：严格符合规范的迁移标注字符串：`Event [Guard] / Action`。
- **【题干取证】**：题干中描述“当发生什么事情时”、“如果满足什么条件”、“系统随即执行什么操作”的复合句。
- **【推理步骤（语法拆解三步）】**：
  1. **找事件（Event）**：触发跃迁的外部信号（动词短语，如 `投币`、`超时`、`点击确认`），写在最前面，**不带任何括号**；
  2. **找守卫条件（Guard）**：触发跃迁必须满足的前提布尔判定（如“金额达到售价”、“重试次数 < 3”），**必须用方括号 `[ ]` 包裹**；
  3. **找动作（Action）**：伴随迁移立即执行的原子操作（如“弹出商品”、“找零”、“记录日志”），**必须紧跟在斜杠 `/` 之后**。
- **【答案形态】**：
  ```text
  (1) 处填: 用户投币 [金额 >= 售价] / 推出商品
  (2) 处填: 超时 [订单未支付] / 取消订单并释放库存
  ```
- **【知识依赖】**：[状态迁移语法要素与两类经典业务流转](#52-两类经典状态机业务流转模型)。
- **【易错与自检】**：
  - *陷阱*：守卫条件漏掉方括号 `[]`；动作漏写斜杠 `/`；
  - *自检*：连线上的标注是否完全符合 `事件 [条件] / 动作` 语法格式？

### 作答卡 UML-ST-03：状态机向面向对象状态模式映射

- **【题型识别】**：常见设问：“该状态机如果使用面向对象设计模式实现，应采用哪种设计模式？指出图中的状态与类的映射关系。”（通常 2～4 分）。
- **【目标产出】**：设计模式名称（**状态模式 State Pattern**）+ 抽象状态类与具体状态子类映射列表。
- **【推理步骤】**：
  1. 识别对象状态改变导致其行为随之改变的特征 → **状态模式（State）**；
  2. 映射准则：
     - 状态机图的每个状态圆角矩形 → 映射为一个**具体状态子类**（如 `BasicState`, `SilverState`, `GoldState`）；
     - 箭线上的触发事件 → 映射为抽象状态类声明的**业务操作接口**（如 `handlePayment()`, `upgrade()`）；
     - 状态的宿主对象 → 映射为**环境上下文类（Context）**。
- **【答案形态】**：
  ```text
  设计模式: 状态模式 (State Pattern)
  映射关系:
  - 环境类 (Context): 会员账户 (MemberAccount)
  - 抽象状态类: MemberState
  - 具体状态类: BasicState (普卡), SilverState (银卡), GoldState (金卡)
  ```
- **【知识依赖】**：[状态机与状态模式双向映射](#53-状态机与面向对象状态模式state双向映射)。

### 作答卡 UML-ST-04：状态三要素（事件/守卫条件/动作）标注提取模板卡

- **【题型识别】**：常见设问：“根据说明，给出状态转换连线上的事件、条件与响应动作” / “写出从状态 S1 转换至 S2 的标注表达式”。（通常 3～5 分）。
- **【标准语法公式】**：
  ```text
  事件名称 [守卫条件] / 执行动作
  ```
- **【题干文本长句拆解流水线（三步提取法）】**：
  1. **找事件（Event）——“谁触发的”**：
     - 寻找句中的外部动词、时间信号或传感器脉冲（如“当顾客按下出纸键”、“计时器超时 30 秒”、“系统收到第三方支付成功回调”）；
     - 提炼为简洁的动词短语（如 `按下出纸键`、`超时`、`支付成功`），**不带任何符号**，放在最开头；
  2. **找守卫条件（Guard）——“在什么前提下才准走”**：
     - 寻找句中的“如果”、“当且仅当”、“若...满足”等条件分支（如“如果纸巾剩余数量大于0”、“若用户账户未被冻结”）；
     - 提炼为布尔判断式（如 `[纸巾剩余量 > 0]`、`[账户正常]`），**必须使用方括号 `[ ]` 严格包裹**；若无条件则省略方括号；
  3. **找动作（Action）——“伴随迁移立即干什么”**：
     - 寻找句中的“系统随之执行...”、“立即输出...”等伴随操作（如“滚轮旋转出纸一节”、“记录出纸日志并扣减积分”）；
     - 提炼为动作短语（如 `推出纸巾并扣减余额`），**必须紧跟在斜杠 `/` 之后**；若无额外操作则省略斜杠。
- **【答案形态】**：
  ```text
  标准答题范例:
  连线 1 标注: 投币 [投入总额 >= 单价] / 推出饮料并找零
  连线 2 标注: 取消交易 / 全额退币
  连线 3 标注: 超时 15 秒 [未确认订单] / 释放锁定的座位
  ```
- **【易错避坑自检】**：
  - *陷阱 1*：漏掉方括号或斜杠（如写成 `投币 (金额足够) 推出饮料`，直接扣除格式分）；
  - *陷阱 2*：把动作当成事件（事件是引发原因，动作是后续结果）；
  - *自检*：检查语法结构是否严格匹配 `Event [Guard] / Action`。

## 3. 典型真题全链路演练与真题锚点

以已验收真题 2016 年下半年试题三（自动售货机状态图与类图建模）（请在历年真题页面查看） 为例，演示从题面到标准答案的全流程：

### 3.1 题面关键信息提炼
- **业务背景**：某种出售罐装饮料的自动售货机（Vending Machine）工作过程：
  1. 顾客选择所需购买的饮料及数量；
  2. 顾客从投币口投入硬币，硬币器收集并计算价值；若金额足够且饮料库存足够，推出饮料并计算找零，顾客取走饮料与找零；若金额不足或饮料库存不足，提示继续投币或重新选择；
  3. 购买结束后清空硬币器，等待下次交易；设退币按钮退还已投硬币。
- **状态图结构**：题干说明用例“购买饮料”包含 4 个核心状态：**“空闲”状态、“准备服务”状态、“可购买”状态以及“饮料出售”状态**。图 3-2 状态图中标注了 S1～S4 四个状态框，以及状态之间的迁移事件 E1～E4。

### 3.2 逐小问推导演练
- **问题 1（识别状态 S1～S4 的名称）**：
  - **取证与推理**：
    - 初始状态：未投币且未选择时处于初始的“空闲”状态 → S1 为“空闲”；
    - 顾客投入硬币后，机器进入“准备服务”状态，等待进一步选择或投币 → S2 为“准备服务”；
    - 当顾客所投硬币达到或超过饮料售价时，系统迁移至“可购买”状态 → S4 为“可购买”；
    - 确认饮料库存充足并出货时，机器进入“饮料出售”状态 → S3 为“饮料出售”。
  - **答案**：`S1: 空闲; S2: 准备服务; S3: 饮料出售; S4: 可购买`（套用 [作答卡 UML-ST-01](#作答卡-uml-st-01状态机要素与状态识别)）。
- **问题 2（识别迁移事件、守卫条件与动作 E1～E4）**：
  - **取证与推理**：
    - E2 触发从“准备服务”到“可购买”的迁移，对应条件为顾客选择饮料且投入金额足够 → E2 为 `选择饮料[硬币足够购买饮料]`；
    - E1 发生在“可购买”状态下选择某种饮料时，若该饮料库存不足则退回“准备服务” → E1 为 `所选购的饮料数量不足`；
    - E3 触发从“可购买”到“饮料出售”的迁移，对应库存足够并执行推出饮料动作 → E3 为 `所选购的饮料数量足够/推出饮料`；
    - E4 是出货完成后回到“空闲”的处理动作 → E4 为 `取走饮料/找零并清空硬币器`。
  - **答案**：
    - `E1: 所选购的饮料数量不足`
    - `E2: 选择饮料[硬币足够购买饮料]`
    - `E3: 所选购的饮料数量足够/推出饮料`
    - `E4: 取走饮料/找零并清空硬币器`（套用 [作答卡 UML-ST-02](#作答卡-uml-st-02反应型与事务型状态流转)）。
- **问题 3（根据系统结构推导类名 C1～C5）**：
  - **取证与推理**：
    - 顶层系统整体为 C1（自动售货机）；
    - 售货机内部聚合了 C2 与 C3，分别对应“硬币器”与“饮料储存仓”；
    - 对应管理的实体对象分别为 C4（硬币）与 C5（饮料）。
  - **答案**：`C1: 自动售货机; C2: 硬币器（或 饮料储存仓）; C3: 饮料储存仓（或 硬币器）; C4: 硬币（或 饮料）; C5: 饮料（或 硬币）`。

## 4. 易错陷阱与交卷自检清单

交卷前花 2 分钟逐项对照以下清单自检：

- [ ] **词性自检**：圆角矩形里的状态名，是否均为**形容词或持续名词短语**？（不能把瞬时触发事件误作持续状态；名称仍以题设术语和语义为准）。
- [ ] **标点符号自检**：迁移线上的守卫条件是否**严密包含在 `[ ]` 内**？动作是否**严密紧跟在 `/` 后**？
- [ ] **异常路径闭环**：检查是否有死状态（除了真正的终态外，每个中间状态都必须有外出的迁移箭线）？
- [ ] **互斥分支完整性**：同一个状态引出两个不同分支时，守卫条件是否互斥（如 `[数量 > 0]` 与 `[数量 <= 0]`）？

## 5. 支撑知识详解（下钻专区）

### 5.1 状态机图的核心要素与辨析规范
```text
[初态 ●] ──> [状态 1] ──事件 [守卫条件] / 动作──> [状态 2] ──> [终态 ◉]
```

| 要素类型 | 识别标志与词性 | 实例表述 | 考场书写规范 |
|---|---|---|---|
| **状态 (State)** | 对象所处的持续性阶段（形容词/名词） | “空闲 (Idle)”、“待付款”、“出货中” | 填入圆角矩形框内 |
| **事件 (Event)** | 瞬时触发的外部输入或信号（动词短语） | “顾客投币”、“用户点击支付”、“超时” | 标注在连线上，无括号 |
| **守卫条件 (Guard)** | 触发迁移必须满足的布尔判定 | `[硬币数量足够]`、`[库存 > 0]` | **必须用方括号 `[ ]` 包裹** |
| **动作 (Action)** | 伴随状态迁移立即执行的原子操作 | `/ 推出商品`、`/ 计算找零`、`/ 发送短信` | **必须紧跟在斜杠 `/` 之后** |

### 5.2 两类经典状态机业务流转模型
1. **交互反应型系统（以自动售货机为例）**：
   - 强调外部事件输入与硬件动作交互：
   - `[空闲 Idle]` ──投币 / 累加金额──> `[已投币]` ──选择商品 [金额 >= 售价] / 推出商品并找零──> `[出货中]` ──出货完成──> `[空闲 Idle]`；
   - 异常路径：`[已投币]` ──按下退币按钮 / 全额退款──> `[空闲 Idle]`。
2. **业务事务全生命周期流转（以订单状态机为例）**：
   - 强调业务对象自创建直至完结的单向/分支流转：
   - `[创建订单]` ──> `S1: 挂起 (Pending)` ──支付成功──> `S2: 备货 (Preparing)` ──发货──> `S3: 已发货 (Shipped)` ──确认收货──> `S4: 已完成 (Completed)`；
   - 异常路径：`S1: 挂起` ──超时未支付 / 释放库存──> `S5: 已取消 (Cancelled)`。

### 5.3 状态机与面向对象状态模式（State）双向映射
- **映射对照表**：
  | 状态机概念 | 面向对象状态模式（State Pattern）对应角色 |
  |---|---|
  | 拥有状态的实体对象 | **环境上下文类 (Context)** |
  | 状态迁移公共契约 | **抽象状态类 / 接口 (State)** |
  | 图中具体的每个圆角矩形 | **具体状态实现类 (ConcreteState)** |
  | 连线上的触发事件 | **抽象状态类中声明的方法** |
  | 守卫条件与分支 | **方法内部的 `if/else` 阈值检查与状态切换** |

### 5.4 经典真题状态机模型复盘与题干拆解（2017-05 电动玩具与 2016-11 自动售货机）

软考真题试题三对状态机的考查，主要集中在以下两大经典领域模型：

#### 1. 自动售货机状态流转模型 (2016-11 真题)
- **四大核心状态**：
  - `S1: 空闲 (Idle)`：售货机通电就绪，未收到投币信号；
  - `S2: 准备服务 (Ready)`：顾客投入第一枚硬币，系统启动计费流程；
  - `S3: 可购买 (Purchasable)`：累计投入金额达到所选饮料单价且该饮料有库存；
  - `S4: 出售中 (Dispensing)`：电机驱动出货滚轮推出饮料，计算并退出找零。
- **典型迁移三要素标注**：
  - `S1 ──投币 / 显示金额──▶ S2`
  - `S2 ──投币 [金额 >= 单价 且 库存 > 0] ──▶ S3`
  - `S3 ──确认购买 / 推出饮料并找零──▶ S4`
  - `S4 ──出货完成 / 清空硬币器──▶ S1`
  - `S2/S3 ──按下退币按钮 / 全额退款──▶ S1`

#### 2. 电动玩具避障与能源状态流转模型 (2017-05 真题)
- **四大核心状态**：
  - `待机 (Standby)`：系统通电未启动行驶任务；
  - `行进 (Moving)`：马达正转前进；
  - `避障转向 (Turning)`：红外超声波测距传感器检测到障碍；
  - `低电量告警 (LowBattery)`：电池电压低于临界值。
- **典型迁移三要素标注**：
  - `行进 ──测距脉冲 [障碍距离 <= 10cm] / 刹车并启动舵机转向──▶ 避障转向`
  - `避障转向 ──转向完成 [航向角偏差 < 5°] / 恢复前进马达──▶ 行进`
  - `任意运行态 ──电量采样 [电量 < 15%] / 发出蜂鸣警报并熄灭大灯──▶ 低电量告警`


## 6. 状态迁移闭卷标注练习

原创题面：订单初始为待支付。支付成功进入待发货；待支付超时则取消并释放库存；待发货确认发货后进入运输中；签收进入已完成。取消和完成均为终结业务状态，不要求再有业务迁移。

```text
初态 -> 待支付
待支付 -- 支付成功 / 记录支付凭证 --> 待发货
待支付 -- 超时 [仍未支付] / 取消订单并释放库存 --> 已取消
待发货 -- 确认发货 / 记录运单号 --> 运输中
运输中 -- 签收 / 记录签收时间 --> 已完成
已取消 -> 终态
已完成 -> 终态
```

拆解示例：“超时”为事件，“仍未支付”为布尔守卫，“取消订单并释放库存”为动作；不得把“取消订单”不加说明地写成条件。无显式事件的完成迁移、内部迁移与自迁移要按题设区别；不能强行要求所有箭线都有事件、条件、动作三项。
