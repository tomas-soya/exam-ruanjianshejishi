# 案例分析真题作答导航与考场核心索引

> 本文档是软件设计师下午科目（案例分析）的**真题实战入口**。考生在考场或刷题时，拿到试题后可直接按照**题面图表特征与小问设问动作**，秒级定位“本问在考什么、从哪里取证、怎么写答案、需要调动哪部分知识”，快速展开作答。

> [!IMPORTANT] 考场分流第一铁律：先按题面特征与小问动作分流；平台精选组卷不得按题号推断领域
> 1. **首选依据**：拿到试题必须**首先根据题面图表视觉特征（DFD/E-R/UML/代码）及具体设问动词**锁定考点领域，再直达对应专题作答卡；
> 2. **题号仅作辅助参考**：
>    - **全国统考标准原卷常规分布**：试题一多为 DFD、试题二为数据库、试题三为 UML、试题四为 C 算法、试题五/六为 Java/C++；
>    - **平台精选组卷（如纳入本知识库的 2024 年两场试卷）**：题号次序被打乱（例如 2024 下半年试题二实为桥接模式 Java 实现，试题三实为回溯算法；2024 上半年试题一实为 UML 类图，试题四实为数据库）。**绝不能依据题号机械推断考点领域，必须始终以题面特征和小问动作为唯一准绳！**

## 1. 案例分析 45 分极速通关应试攻略（田忌赛马·风险预算版）

> [!TIP] **先把“保底分”改成“风险预算”**
> 1. **目标仍是 45 分**：应用技术满分 75 分，全国一般合格标准按满分 60% 执行时即为 45 分。冲刺阶段不需要追求满分，但模拟训练应争取稳定达到 **48～52 分**，给临场波动留出安全垫。
> 2. **2026 年时间规则已变化**：初、中级资格的“基础知识 + 应用技术”两科连考，总作答时长 240 分钟；基础知识最短 90 分钟、最长 120 分钟，节余时长可用于应用技术。因此应用技术实际可用时间是 **120～150 分钟**，不是固定 150 分钟。选择题已有把握时，可在不牺牲正确率的前提下争取约 90～100 分钟完成第一科。
> 3. **分数区间不是统计学保证**：本仓库 2024 年两场为题库精选组卷，2016～2023 年材料也标注为平台试题集合、统考身份待逐项核验。下表用于制定训练优先级，不代表真实考试中“必拿”或“保底”分。
> 4. **考场顺序按题型和个人强弱动态决定**：不要死记“1→3→5→2→4”。进入应用技术后先快速浏览题面，优先做自己最稳定的高收益题，把算法等容易超时的题放到后段并设置止损线。
>
> 2026 年连考规则参考：[南京市工业和信息化局《2026 年下半年计算机软件资格考试南京考区考试安排》](https://gxj.nanjing.gov.cn/njsjjhxxhwyh/202609/t20260924_5916907.html)。

### 1. 案例五大题型性价比与“田忌赛马”得分蓝图

| 题型 | 历年材料中的主要拿分点 | 冲刺定位 | 建议训练目标 | 熟练后上限 |
|---|---|---|:---:|:---:|
| **DFD** | 实体/存储识别、缺失数据流、父子平衡、数据流组成 | **固定主粮仓**：题型结构最稳定，优先练到低失误 | **10～13 分** | 15 分 |
| **Java 设计模式** | 类图角色、接口/继承、成员声明、构造/实例化、委托调用 | **固定主粮仓**：模板化程度高，但空位数量并非固定为 5 | **9～12 分** | 15 分 |
| **UML** | 用例/类名、多重度、属性方法、关系与模式识别 | **候选第三粮仓**：与数据库做真题测速后择强 | **8～12 分** | 15 分 |
| **数据库** | E-R 联系、关系模式、主外键、范式与需求扩展 | **候选第三粮仓**：按给分点取舍，不按“小问编号”机械截断 | **8～11 分** | 15 分 |
| **算法** | 算法思想/复杂度/稳定性/结果推演、代码浅层空位 | **限时扫分区**：先拿非代码分，再尝试明显代码空 | **2～5 分 + 奖金分** | 15 分 |

> **风险预算的正确用法**
> - 不再使用“DFD 13 + UML 12 + Java 11 = 36，所以数据库再拿 10 就稳过”的乐观叠加。
> - 一个更保守的起点可以是：DFD 11 + Java 10 + UML/数据库强项 10 + 另一门 8 + 算法 3 = **42 分**。
> - 因此模拟训练不能只追求“算出来刚好 45”，而应把可重复成绩推到 **48～52 分**；这 3～7 分才是真正的安全垫。
> - UML 与数据库谁是第三粮仓，不由题号决定：连续做 2～3 套限时真题，谁单位时间得分更高、波动更小，就优先谁。

### 2. 三大极速攻坚战术（风险预算版）

#### 战术一：先锁定两个固定主粮仓——DFD + Java 设计模式

1. **DFD：目标 10～13，熟练后冲 15**
   - 优先拿实体/存储识别与缺失数据流，这些小问最适合通过“题干—图形对账”训练稳定性。
   - 父子平衡、加工逻辑、数据流组成等最后一问并不总是送分，不能把接近满分写入“保底预算”。
   - 训练时必须写完整三元组“数据流名称、起点、终点”，并核对实体—加工—存储之间的合法连接。
   - 对应：[01 结构化分析与设计](01-结构化分析与设计.md)。

2. **Java 设计模式：目标 9～12，熟练后冲 15**
   - “五大空位法”应理解为 **五类常见空位**，不是“每卷固定五个空”。仓库材料中已经存在 6 个空的题目。
   - 优先掌握：接口/继承声明、多态成员声明、构造与初始化、对象创建、委托调用；再用类图角色关系校验类型和方法名。
   - 训练目标不是“背完 23 种模式”，而是看到类图后能迅速确定角色关系，并能从上下文还原常见 Java 语句。
   - 对应：[02 面向对象设计模式与 Java 实现](02-面向对象设计模式与Java实现.md)。

#### 战术二：UML / 数据库真题测速，选出第三粮仓

- 用 2～3 套历年材料分别限时做 UML 与数据库，记录“得分 / 分钟”和错误类型。
- **UML 若更强**：重点练用例/类名映射、多重度、include/extend、属性方法和模式识别。
- **数据库若更强**：重点练 E-R 联系、多重度、关系模式、主外键和常见范式。
- 数据库尤其不要执行“只做前两问”的机械策略：历年材料中前两问合计分值并不稳定，有的只有 7～9 分。正确做法是 **先扫全题，再按给分点难度取舍**；第三问中若有简单主外键、局部扩展或范式判断，仍应继续拿分。
- 对应：[03 UML 类图](03-UML类图与面向对象分析.md)、[04 数据库设计与关系模式](04-数据库设计与关系模式.md)。

#### 战术三：算法题先扫非代码分，再设 15～20 分钟止损线

1. **先扫非代码小问**：算法思想、时间/空间复杂度、稳定性、给定实例的结果等，能直接判断的先写。
2. **再扫代码浅层空位**：循环初值/边界、数组下标、明显状态转移、返回值等；看得出就填。
3. **不要预记“4～6 分”**：历年材料并非每套都有“算法策略 + 复杂度”两项固定送分，有的卷子复杂度只有 2 分，甚至没有独立的策略名称得分点。
4. **硬止损**：算法累计投入 15～20 分钟后，如果继续阅读代码不能明显增加得分，就标记未完成处并撤出，把时间留给前三/四个更稳定模块的补漏与检查。
5. 对应：[08 算法设计与分析](08-算法设计与分析.md)。

### 3. 考场实战顺序与弹性时间管理

**第一原则：应用技术时间 T = 240 - 基础知识实际用时，因此 T 在 120～150 分钟之间。** 不再按固定 150 分钟硬套时间表。

推荐的题型顺序是：

~~~text
先快速浏览全卷（约 3～4 分钟）
→ DFD（通常优先）
→ Java / UML / 数据库三者按个人模拟成绩从强到弱
→ 算法放后段，15～20 分钟止损
→ 回到所有标记题与格式检查
~~~

> 如果模拟结果显示 DFD 并非你的稳定强项，也不要为了“题号传统”硬守顺序；原则始终是 **单位时间得分 + 波动最小**。

**当应用技术有约 150 分钟时：**

| 阶段 | 建议预算 |
|---|---:|
| 快速浏览、标记强弱题 | 4 分钟 |
| DFD | 24 分钟 |
| Java/UML/数据库最强项 | 24 分钟 |
| 第二强项 | 22 分钟 |
| 第三项 | 23 分钟 |
| 算法 | 最多 18 分钟 |
| 回防、补空、格式与交卷检查 | **35 分钟** |

**当应用技术只有约 120 分钟时：**

| 阶段 | 建议预算 |
|---|---:|
| 快速浏览、标记强弱题 | 3 分钟 |
| DFD | 20 分钟 |
| Java/UML/数据库最强项 | 20 分钟 |
| 第二强项 | 18 分钟 |
| 第三项 | 18 分钟 |
| 算法 | 最多 14 分钟 |
| 回防、补空、格式与交卷检查 | **27 分钟** |

这些数字是“上限预算”而不是强制铃声：某题提前完成，就把时间转移给标记题或检查；某题超过预算仍没有明显新增得分，就立即撤出。

### 4. 考前极速冲刺执行法（3～5 天）

- **Day 1：诊断 + 选第三粮仓**  
  选 2 套材料，分别限时做 DFD、Java、UML、数据库、算法的关键小问。记录实际得分、耗时和错误类型；当天结束前确定“DFD + Java + UML/数据库较强者”的 **2+1 主攻结构**。

- **Day 2：固定粮仓提稳定性**  
  专攻 DFD + Java。DFD 重点把实体/存储/补流做到低失误；Java 用类图角色还原代码，覆盖至少 3 种不同设计模式。目标不是刷数量，而是让同类错误不重复出现。

- **Day 3：第三粮仓 + 弱项最低可用能力**  
  主攻 UML/数据库中的强项；弱项只保留高性价比基本功。算法只练“先扫非代码分 + 明显代码空 + 15～20 分钟撤退”。

- **Day 4（有 4～5 天时）：第一次完整模拟**  
  按真实连考思路控制时间。如果基础知识已经较稳，可按 90～100 分钟完成第一科、给应用技术留下约 140～150 分钟的节奏模拟。应用技术不按题号，按“浏览 → 强项优先 → 算法止损 → 回防”执行。

- **Day 5（有 5 天时）：错因回炉 + 第二次模拟**  
  只修第一次模拟中真正丢分的动作：漏看限定词、图文对账错误、多重度方向错、主外键遗漏、Java 类型/方法名错、算法超时等。第二次完整模拟的目标是 **稳定达到 48～52 分，而不是偶然碰到 45 分**。

## 3. 考场破题与解题通用五步流程

无论面对哪一道案例大题，建议考生严格遵循以下标准化五步作答流程：

```text
第 1 步：看题面，按图表特征定领域（依据题面图表特征识别领域，标准卷题号仅作辅助参考）
  ↓
第 2 步：审小问，映射作答原型（弄清本问“最终要交出什么格式的答案”）
  ↓
第 3 步：准取证，从题干/图表中圈定唯一支撑依据（排除无关叙述）
  ↓
第 4 步：循步骤，执行推理并组织规范答案（套用各题型作答卡推导流程）
  ↓
第 5 步：查清单，对照易错陷阱进行闭环自检（检查主外键/起点终点/语法分号）
```

1. **第 1 步：看题面，按图表特征定领域（标准卷题号仅作辅助参考）**：
   - 快速审视题面核心载体：
     - 若为顶层图/0层图/加工/数据存储 → 进入 [01 结构化分析与设计 (DFD)](01-结构化分析与设计.md)；
     - 若为实体联系图/关系模式/范式分解 → 进入 [04 数据库设计与关系模式](04-数据库设计与关系模式.md)；
     - 若为用例图/类图/状态图/活动图/序列图 → 进入对应 UML 专题（[03](03-UML类图与面向对象分析.md)、[05](05-UML用例图与活动图.md)、[06](06-UML序列图与关系.md)、[07](07-UML状态图与状态转换.md)）；
     - 若为算法描述、状态转移方程、C 函数伪代码 → 进入 [08 算法设计与分析](08-算法设计与分析.md)；
     - 若为设计模式类图与 Java/C++ 代码填空 → 进入 [02 面向对象设计模式与Java实现](02-面向对象设计模式与Java实现.md)；
   - **特别提醒**：对于平台精选组卷或乱序试卷，绝对不要凭题号猜测考点，必须以图表类型为准。
2. **第 2 步：审小问，映射作答原型**：
   - 先读题目下面的具体【问题 1】、【问题 2】、【问题 3】；
   - 明确目标产出：是要写“实体名称”、“数据流三元组”、“主外键”、“代码填空”还是“中文简答理由”；
   - 带着具体目标返回题干取证，避免漫无目的地反复通读全文。
3. **第 3 步：准取证，圈定唯一支撑依据**：
   - DFD：圈出名词（潜在实体/存储）与动词（潜在加工与数据流向）；
   - 数据库：圈出业务数量词（“一个”、“多个”、“每项”）与时间属性；
   - UML：圈出边界角色、共有/特有属性以及生命线创建时序；
   - 算法：圈出状态物理定义、循环边界变量与递归终止分支；
   - 设计模式：圈出职责分配、可变化点与持有对象引用。
4. **第 4 步：循步骤，执行推理并组织规范答案**：
   - 严格按照各作答卡给出的推理步骤执行；
   - 书写必须符合官方标准答案形态：
     - 数据流必须写清“名称、起点、终点”；
     - 主键必须用文字显式说明或下划线清晰标注，外键必须指出引用关系；
     - 代码填空严格遵守语法（大小写、指针 `*` 与箭头 `->`、语句末尾分号）。
5. **第 5 步：查清单，闭环自检**：
   - 交卷前快速对照专题文末的“易错与交卷自检清单”排查失分点，确保每一小问答案无漏洞。
