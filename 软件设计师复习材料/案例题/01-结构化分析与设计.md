# 结构化分析与设计案例：数据流图（DFD）

> 本专题专为软考下午试题一（数据流图 DFD，15 分必答题）定制。考生拿到试题后，可依据具体小问设问类型，直接定位对应的作答卡快速展开作答。

---

## 1. DFD 题型识别与考场通用破题流程

### 1.1 试题识别与题面结构
- **试题位置**：下午试题一（必答题，满分 15 分）。
- **题面三件套**：
  1. **系统业务说明**：按段落陈述系统的外部参与者、核心功能处理逻辑、持久化记录要求及数据流转过程；
  2. **图 1 顶层 DFD（环境图）**：将整个系统视为单一加工（编号通常为 0），呈现系统与外部实体之间的宏观输入与输出；
  3. **图 2 细化 0 层 DFD（或局部 1 层/2 层图）**：将系统分解为若干具体子加工（P1~Pn）、数据存储（D1~Dn）及内部数据流。

### 1.2 考场四步快速解题流水线
```text
第 1 步：扫视说明，划定边界 → 圈出系统外角色（外部实体）与系统内静态文件（数据存储）
  ↓
第 2 步：父子对照，平衡检查 → 比对顶层图与 0 层图边界数据流，锁定缺失或名称不一致的数据流
  ↓
第 3 步：紧扣动词，推演内部 → 依据业务说明中“查询/保存/通知”动词，为内部加工补齐输入与输出
  ↓
第 4 步：闭环核对，规避陷阱 → 检查连线合法性（严禁非法直连），复核是否有黑洞/奇迹/灰洞
```

## 2. DFD 核心作答卡

### 作答卡 DFD-01：识别外部实体

- **【题型识别】**：常见设问：“使用说明中的词语，给出图中的实体 E1～En 的名称。”（通常 3～5 分）。
- **【目标产出】**：实体编号对应的名称列表（如 `E1: 客户; E2: 采购部门; E3: 库房`）。
- **【题干取证】**：
  - 重点阅读业务说明的前两段及各功能描述句的主语/宾语；
  - 寻找位于系统边界之外、与系统发生信息交互的**人（如经理、客户、会员）**、**外部机构/部门（如供应商、库房、财务部）**或**外部系统/第三方平台（如证券交易中心、银行接口、天气预报服务）**。
- **【推理步骤】**：
  1. 查看图 1 顶层图中各矩形框 `E1～En` 连接的数据流流向；
  2. 若某实体向系统发送“订单/请求/申请”，或系统向其输出“报表/通知/确认信息”，在题干中定位该输入输出句的发送者或接收者；
  3. 核对实体个数与题干角色一一对应，排除系统内部加工；人员是否为外部实体由题设系统边界判断。
- **【答案形态】**：严格忠实于题干原词，写名词短语（如“证券交易中心”、“居民”）。
- **【知识依赖】**：[四类元素识别与系统边界](#51-从题干拆出数据流图的四类元素)。
- **【易错与自检】**：
  - *陷阱*：误将系统内部的加工（如“处理订单”）或内部数据表当作外部实体；
  - *自检*：该实体是否脱离本系统而独立存在？若是系统内功能，绝不能填为外部实体。

### 作答卡 DFD-02：识别数据存储

- **【题型识别】**：常见设问：“使用说明中的词语，给出图中的数据存储 D1～Dn 的名称。”（通常 3～5 分）。
- **【目标产出】**：存储编号对应的名称列表（如 `D1: 订单记录; D2: 库存表`）。
- **【题干取证】**：
  - 在题干说明中圈出带“**记录、文件、表、档案、库、清单**”等体现持久化保存的名词短语；
  - 观察 0 层图中连接数据存储 `D1～Dn` 的数据流（流入该存储表示“保存/写入”，流出表示“读取/查询”）。
- **【推理步骤】**：
  1. 顺着指向 `Di` 的输入数据流反查：是哪个加工在“记录/更新/保存”什么信息？
  2. 顺着从 `Di` 引出的输出数据流反查：是哪个加工在“查询/对照/统计”什么信息？
  3. 结合两端数据流的语义，匹配题干中最贴切的持久化文件名词。
- **【答案形态】**：严格采用名词短语，绝不使用动宾短语。
- **【知识依赖】**：[数据存储命名原则](#52-数据存储命名与读写规则)。
- **【易错与自检】**：
  - *陷阱*：将加工名称填在数据存储位置（如误填为“进货处理”、“库存统计”）；
  - *自检*：该项是否能被保存并供后续加工反复查询？若包含动词操作，立即修正为对应名词。

### 作答卡 DFD-03：补充缺失数据流

- **【题型识别】**：常见设问：“根据说明和图中的术语，补充图 1-2 中缺失的数据流及其起点和终点。”（通常 4～6 分）。
- **【目标产出】**：三元组形式：`数据流名称 | 起点 | 终点`。
- **【题干取证】**：
  - 取证点 A（父子平衡）：顶层图对外的数据流列表 vs 0 层图边界对外数据流列表；
  - 取证点 B（加工守恒）：题干中明确说明“加工 A 将 X 发送给加工 B / 写入存储 D”，但图中无此连线；
  - 取证点 C（动词方向）：题干中“读取、查询、生成、发送、打印”对应的源和宿。
- **【推理步骤】**：
  1. **先做父子图平衡检查**：对比顶层图与 0 层图，若顶层图有流 `E1 → 系统` 名为“申请单”，而 0 层图 `E1` 到任何加工均无“申请单”流，立即补出 `起点: E1, 终点: 加工Px`；
  2. **再做加工内部数据守恒核查**：排查 0 层图中的每个加工：
     - 若某加工只有输入没有输出（黑洞），或者只有输出没有输入（奇迹），必有漏流；
     - 结合题干描述，该加工根据什么数据生成输出？找出从外部实体或存储到该加工的缺失输入流；
  3. **依据动词确定箭头方向**：
     - 查询/读取：`数据存储 → 加工`；
     - 写入/更新：`加工 → 数据存储`；
     - 提交/请求：`外部实体 → 加工`；
     - 通知/结果：`加工 → 外部实体`。
- **【答案形态】**：建议按清晰表格或分行罗列，必须写清**名称、起点、终点**：
  ```text
  数据流名称: 交易结果通知, 起点: 加工P3(证券交易), 终点: E1(客户)
  数据流名称: 库存查询, 起点: D1(库存记录), 终点: 加工P2(缺货统计)
  ```
- **【知识依赖】**：[顶层图与 0 层图平衡](#53-顶层图与-0-层图必须平衡)、[动词与连线方向对照表](#54-用题干动词校验方向)。
- **【易错与自检】**：
  - *陷阱*：只写了数据流名称，漏写起点或终点；箭头方向颠倒；
  - *自检*：所补数据流的两端中，**是否至少有一端是“加工”**？如果两端都是实体或存储，必错！

### 作答卡 DFD-04：加工分解与子图细化规范（含错误流修正）

- **【题型识别】**：常见设问：“给出加工 Pn 细化分解后的子加工 Pn.1～Pn.k 的名称及其输入输出数据流” / “指出图中的错误数据流并说明理由，给出纠正后的数据流。”（通常 3～6 分）。
- **【目标产出】**：
  1. 细化子加工编号、动宾短语名称、局部数据存储与内部数据流；
  2. 错误数据流识别、违背规则理由阐述及纠正方案（删错线、经过加工中介补正线）。
- **【题干取证】**：
  - 定位题干中对某特定复杂业务步骤（如“结算处理”、“核保审核”）的具体子步骤描述；
  - 检查图中所有图元间的直连连线是否违背加工中介铁律；
  - 检查数据流方向是否违背“申请进、通知出、日志存”的业务常理。
- **【推理步骤（加工细化与纠错流水线）】**：
  1. **第一步：子加工编号与动宾命名**：
     - 若父加工为 `P3`，其细化子加工统一编号为 `P3.1`、`P3.2`、`P3.3`；
     - 每个子加工必须使用“动词 + 宾语”命名（如 `P3.1: 校验支付凭据; P3.2: 扣减用户积分; P3.3: 生成对账凭证`），严禁纯名词；
  2. **第二步：父图端点穿透与局部守恒**：
     - 父加工 `P3` 拥有的外部输入流（如“支付凭据”），在子图中必须精确连入承担该起始职责的具体子加工（如 `P3.1`）；
     - 父加工 `P3` 拥有的外部输出流（如“对账单”），在子图中必须由产生该结果的末端子加工（如 `P3.3`）引出；
     - 子加工之间流动的数据流为**内部数据流**，仅在子图内部流转，不穿透到父图；
  3. **第三步：排查“三大非法直连”**：
     - 坚决查杀：`外部实体 ↔ 外部实体` 直连（系统无法感知外部实体之间的私下交互）；
     - 坚决查杀：`外部实体 ↔ 数据存储` 直连（外部实体绝不能越过加工直接读写数据库）；
     - 坚决查杀：`数据存储 ↔ 数据存储` 直连（数据表之间不会凭空自拷贝，必须通过加工搬运）；
  4. **第四步：排查“加工数据守恒黑洞/奇迹”**：
     - **黑洞**：某子加工只有输入流，没有输出流（数据被吞噬）；
     - **奇迹**：某子加工只有输出流，没有输入流（凭空产生数据）；
     - **灰洞**：输入数据不足以产生输出数据（如输入仅有“学号”，输出却包含了“家庭住址与考试成绩”）。
- **【答案形态】**：
  ```text
  【加工细化示例】
  子加工名称: P2.1 验证资格, P2.2 扣除费用, P2.3 打印凭证
  内部数据流: 合格通知 (P2.1 -> P2.2), 扣费凭条 (P2.2 -> P2.3)
  
  【错误数据流纠错示例】
  错误数据流: 规则文件（起点: 外部实体E2，终点: 数据存储D1）
  理由: 外部实体与数据存储之间不能直接相连，数据流两端必须至少有一端是加工。
  纠正方案: 删除该数据流，增加数据流“提交规则”（E2 -> 加工P1）和数据流“写入规则”（加工P1 -> D1）。
  ```
- **【知识依赖】**：[DFD 连线合法性铁律](#55-dfd-连线合法性处理是必要中介)、[加工数据守恒与动宾短语命名](#56-加工数据守恒与动宾短语命名)。
- **【易错与自检】**：
  - *陷阱*：子图细化时自己虚构了外部输入流，导致与父图不平衡；
  - *自检*：子图中所有连向图外的流，其名称和数量是否与父图完全一致？

### 作答卡 DFD-05：父子图平衡与数据守恒快速核查卡

- **【题型识别】**：常见设问：“解释图 X（顶层图）和图 Y（0层图）是否保持平衡，若不平衡请说明原因 / 如何保持平衡？”（通常 3～5 分）。
- **【目标产出】**：明确结论（平衡 / 不平衡）+ 差异数据流清单（缺失流/多余流及其端点）+ 保持平衡规范概念。
- **【题干取证】**：对比父图（顶层 DFD）中对应加工（通常为系统加工 0）的所有外接数据流，与子图（0 层 DFD）中与外部实体之间的全部数据流。
- **【推理步骤（父子平衡核对矩阵法）】**：
  1. **构建输入流对账集**：
     - 列出父图中从各外部实体指向系统的输入流集合：`In_parent = { 流名1 (E1 -> 系统), 流名2 (E2 -> 系统), ... }`；
     - 列出子图中从各外部实体指向各子加工的输入流集合：`In_child = { 流名1 (E1 -> P1), 流名2 (E2 -> P2), ... }`；
  2. **构建输出流对账集**：
     - 列出父图中从系统指向各外部实体的输出流集合：`Out_parent = { 流名3 (系统 -> E1), ... }`；
     - 列出子图中从各子加工指向各外部实体的输出流集合：`Out_child = { 流名3 (P3 -> E1), ... }`；
  3. **比对核查与异常分类**：
     - **完全平衡**：`In_parent == In_child` 且 `Out_parent == Out_child`；
     - **子图缺流**：父图有的流子图漏画（最常见，如子图缺少 `E1 -> P1` 的“挂号请求”）；
     - **子图多流**：子图凭空多出连接外部实体的连线；
     - **数据流打包与拆解**：若父图为宏观数据流（如“报销申请包”），子图拆为“发票明细”和“审批单”，若题干明确说明包含关系则视为平衡，否则指出命名不一致。
  4. **给出标准平衡定义阐述**：
     - “分层数据流图中的父图与子图平衡是指，父图中某个加工的输入输出数据流必须与该加工分解后子图的总输入输出数据流在数量、名称和方向上保持完全一致。”
- **【答案形态】**：
  ```text
  判定: 图 1 与 图 2 不平衡。
  原因: 
  1. 顶层图 1 中存在从外部实体 E1 到系统的输入数据流“挂号申请”，但在 0 层图 2 中缺失该输入数据流；
  2. 0 层图 2 中存在从加工 P3 到外部实体 E2 的输出数据流“处方单”，但在顶层图 1 中缺失该输出数据流。
  如何保持平衡: 父图中某个加工的输入输出数据流必须与该加工分解后子图的总输入输出数据流完全一致。应在图 2 中为加工 P1 补充从外部实体 E1 输入的“挂号申请”数据流，并在图 1 中补充从系统到外部实体 E2 的“处方单”数据流。
  ```
- **【知识依赖】**：[顶层图与 0 层图必须平衡](#53-顶层图与-0-层图必须平衡)。

### 作答卡 DFD-06：补充与命名加工

- **【题型识别】**：常见设问：“给出图 1-2 中加工 P1～Pn 的名称。”（通常 3～6 分）。
- **【目标产出】**：加工编号对应的动宾短语名称（如 `P1: 审核资格; P2: 统计销售额`）。
- **【题干取证】**：根据题干业务步骤（“第一步系统先...接着...随后...”），对应 0 层图的处理流程编号。
- **【推理步骤】**：
  1. 寻找加工 `Pi` 的输入数据流和输出数据流；
  2. 提炼输入转换到输出的核心业务动作动词；
  3. 组合为“动词 + 宾语”的动宾短语，字数通常为 4～8 个字。
- **【答案形态】**：动宾短语（如“生成账单”、“审核订单”、“交易撮合”）。
- **【知识依赖】**：[加工命名动宾规范](#56-加工数据守恒与动宾短语命名)。

### 作答卡 DFD-07：数据流组成与数据字典

- **【题型识别】**：常见设问：“根据说明，给出‘某某’数据流的组成” / “用数据字典形式表示”。
- **【目标产出】**：数据项枚举清单，或使用 DD 符号构成的定义式。
- **【题干取证】**：在题干业务描述中定位该数据流名称，摘取紧随其后的“包含...、由...构成、包括...”语句。
- **【推理步骤】**：
  1. 忠实于题干原词提取子项，绝不臆造未提及的字段；
  2. 若要求数据字典符号：
     - 顺序连接用 `+`；
     - 选其一用 `[ A | B ]`；
     - 重复出现用 `{ A }`；
     - 可选字段用 `( A )`。
- **【答案形态】**：
  - 纯文本形式：`农事信息 = 农事活动信息 + 农事过程信息 + 地块信息`；
  - 符号规范：`体检预约单 = 身份证号 + 姓名 + 预约科室 + [ 上午 | 下午 ] + ( 既往病史 )`。
- **【知识依赖】**：[数据字典核心定义符号速查](#57-数据字典data-dictionary核心描述符号速查)。

### 作答卡 DFD-08：系统扩展与修改说明

- **【题型识别】**：常见设问：“现系统新增某某功能需求，针对该需求，需要对图 1 和图 2 进行哪些修改，请用文字说明。”（通常 3～5 分）。
- **【目标产出】**：分条陈述的修改要点（新增外部实体、新增数据存储、新增加工、新增数据流及其两端）。
- **【题干取证】**：题干最后一节的新增业务需求段落。
- **【推理步骤】**：
  1. 是否有新主体引入？→ “在图 1 和图 2 中增加外部实体 X”；
  2. 是否有新数据需要长期留存？→ “在图 2 中增加数据存储 D”；
  3. 需要哪些业务处理？→ “在图 2 中增加加工 P（动宾短语）”；
  4. 数据如何流动？→ “增加从实体 X 到加工 P 的数据流 Y，增加从加工 P 到存储 D 的数据流 Z”。
- **【答案形态】**：条理分明列出点：
  ```text
  1. 在图 1 和图 2 中增加外部实体“证券交易中心”；
  2. 在图 2 中增加加工“证券交易”，在图 1 和图 2 中增加由“证券交易”发往“证券交易中心”的数据流“交易信息”；
  3. 增加由“证券交易中心”返回“证券交易”加工的数据流“交易结果”，并新增指向数据存储“交易记录”的写入流。
  ```

### 作答卡 DFD-09：加工逻辑与结构化工具

- **【题型识别】**：常见设问：“采用结构化语言对某加工逻辑进行描述” / “写出结构化分析阶段常用的五大工具”。
- **【目标产出】**：结构化伪代码块，或工具名词列表。

## 5. 支撑知识详解（下钻专区）

### 5.1 从题干拆出数据流图的四类元素
| 元素 | 图形符号 | 识别线索 | 考场作用 |
|---|---|---|---|
| **外部实体 (Entity)** | 矩形框 | 客户、供应商、经理、银行系统、库房 | 系统边界外的数据源或宿 |
| **加工 (Process)** | 圆形 / 圆角矩形 | 审核、统计、计算、生成、处理（动宾短语） | 执行数据逻辑变换 |
| **数据存储 (Data Store)** | 双平形线 / 开口矩形 | 订单表、库存文件、档案记录、日志库（名词） | 静态持有持久化数据 |
| **数据流 (Data Flow)** | 命名带箭头的实线 | 订单单据、报表、通知、查询结果、认证数据 | 传递中的数据内容 |

### 5.2 数据存储命名与读写规则
- 必须使用业务名词短语（如“库存记录”、“委托记录”），切忌写成加工名；
- 同一存储可被多个加工反复读写，不因被两个加工访问就画两个独立存储。

### 5.3 顶层图与 0 层图必须平衡
- **平衡原理**：父图中的某个加工分解为子图后，该加工对外的所有输入流与输出流，在子图边界上必须完全保留，不能凭空增删对外数据流。子图内部可以增设仅在子图流转的加工、数据存储及内部数据流。

### 5.4 用题干动词校验方向
| 题干常见动词 | 数据流标准流向 |
|---|---|
| 接收、受理、读取、输入、提取、根据…比对 | `外部实体 / 数据存储 → 加工` |
| 保存、记录、存入、更新、写入、修改 | `加工 → 数据存储` |
| 发送、打印、开具、通知、反馈、呈现、输出 | `加工 → 外部实体` |
| 提交、录入、申报、发起申请 | `外部实体 → 加工` |

### 5.5 DFD 连线合法性：处理是必要中介
- **连线铁律**：数据流的两端中，**至少有一端必须是“加工”**！
- 绝对非法的四类连线：
  1. `外部实体 ──▶ 外部实体`（系统无法感知外部交互）；
  2. `外部实体 ──▶ 数据存储`（实体不能越权读写数据库）；
  3. `数据存储 ──▶ 外部实体`（数据库不会主动向外部输出）；
  4. `数据存储 ──▶ 数据存储`（数据存储之间没有自发的复制能力）。

### 5.6 加工数据守恒与动宾短语命名
- **黑洞（Black Hole）**：加工只有输入流，没有输出流（数据吞噬）；
- **奇迹（Miracle）**：加工只有输出流，没有输入流（凭空产生）；
- **灰洞（Gray Hole）**：输入流的数据项不足以支撑计算出输出流所需的内容；
- 加工必须命名为**动宾短语**（动词+名词，如“验证用户身份”、“生成结算月报”）。

### 5.7 数据字典（Data Dictionary）核心描述符号速查
| 符号 | 语法含义 | 典型案例 |
|:---:|---|---|
| `=` | 被定义为 | `开票信息 = 客户名称 + 税号 + 金额` |
| `+` | 与（顺序连接） | 必选的连续数据项相接 |
| `[ \| ]` | 或（多选一） | `付款方式 = [ 微信 \| 支付宝 \| 现金 ]` |
| `{ }` | 重复（0次至多次） | `{ 选购商品 }` 或 `1{ 选购商品 }50` |
| `( )` | 可选（0次或1次） | `( 附加备注说明 )` |
| `" "` 或 `..` | 基本字符常量 / 范围 | `1..100` 或 `"男" \| "女"` |

### 5.8 结构化分析五大核心工具
1. **数据流图（DFD）**：建模系统功能与数据流转视图；
2. **数据字典（DD）**：对 DFD 中所有图元数据项给出精确规范定义；
3. **结构化语言**：采用受限控制结构（顺序、选择、循环）表达加工算法；
4. **判定表（Decision Table）**：在条件复杂组合时，清晰表达条件与动作对应关系；
5. **判定树（Decision Tree）**：图形化展示多条件多分支决策逻辑。

### 5.9 外部实体辨析矩阵（内部人员 vs 外部实体）

软考案例试题一中，外部实体识别最容易在“人员角色与系统内部模块”之间产生混淆。下表梳理了高频考查的典型边界辨析：

| 实体分类 | 典型角色 / 示例 | 是否为外部实体 | 判定规则与采分依据 |
|---|---|:---:|---|
| **外部人员** | 客户、读者、患者、考生、会员、供应商销售代表 | **是** | 位于系统之外，通过人机界面向系统提交请求或接收系统产出结果 |
| **系统操作员** | 挂号收费员、图书管理员、仓库管理员、调度员 | **是** | 虽为组织内部员工，但从软件系统边界来看，属于软件的人机交互操作者，向系统录入数据 |
| **外部系统/平台** | 银行支付网关、社保结算系统、短信服务平台、气象数据接口 | **是** | 独立于本系统之外运行的第三方系统，通过接口进行网络数据交换 |
| **外部物理设备** | IC卡读卡器、温湿度传感器、条码扫描枪、打印机 | **是** | 硬件接口设备，作为数据的物理输入源或输出目的地 |
| **内部功能模块** | 权限验证模块、报表生成器、自动结算程序 | **否（是加工）** | 系统内部的数据处理逻辑单元，属于 DFD 中的圆圈加工，绝不能当成外部实体 |
| **内部数据表/库** | 用户信息表、订单主表、日志文件、配置档案 | **否（是存储）** | 静态持有持久化数据的容器，属于 DFD 中的数据存储，绝不能当成外部实体 |

## 6. 边界、组成与缺失流的迁移练习

外部实体由模型边界决定，不由是否是本单位员工、设备或“管理人员”决定。学校的信息系统可以把教务人员作为外部实体；嵌入式控制软件也可把传感器、执行器作为外部实体。沿实际箭头判断数据源与数据宿；同一实体可以既输入又接收输出。

数据流组成只列该数据流包含的数据项及结构，不强制每个数据流都出现主键。例如媒体流可定义为 `[JPG 图片 | AVI 视频]`，控制信号可定义为 `[低档 | 中档 | 高档]`。只有业务识别确需时才包含编号；不能把数据库主键要求机械套入控制信号。

原创练习：预约系统边界外有患者和护士，内部加工为 P1 登记预约、P2 查询排班，存储为 D1 预约表、D2 排班表。题设要求护士维护排班，患者提交预约并收到结果。现有流只有“患者→P1：预约申请”“P1→D1：预约记录”“D2→P2：排班信息”。写出必须补充的交互，不改变系统边界。

参考检查：护士提交排班先到维护排班加工，再写 D2，不能护士直连 D2；P1 需向 P2 发排班查询并接收结果；P1 向患者发预约结果。若图中没有维护加工，需明确建议补加工与流，不能凭空把它当作已给空位的唯一答案。逐句对账应列“数据流名称、起点、终点”，父图已有边界流在子图要有等价对应。

自测：预约结果只需表达成功或失败原因，是否一定要加患者主键？（由接口需求决定；不能仅因它是数据流就强制加入主键。）
